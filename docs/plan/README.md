# helpdesk 実装計画

`piconic-ai/helpdesk` を、核から同梱の拡張、CLI、MCP、セルフホストの手順まで作るための計画です。段階1から4まで、順に、止まらずに作り進めてください。

## 読む順番

最初に、共通の決まりをすべて読みます。

| ファイル | 内容 |
|---|---|
| `00-overview.md` | 何を作り、何を作らないか |
| `01-references.md` | 実装の前に読むものと、技術スタック |
| `02-defaults.md` | 決まっていない事項の既定値 |
| `03-design.md` | 設計の決まりと、リポジトリの構成 |
| `04-workflow.md` | 進め方、止まって確認する場合、報告の形式 |
| `05-verification.md` | 検証の手段と、人の確認として残すもの |

次に、段階ごとのファイルを、その段階に入るときに読みます。

| ファイル | 段階 |
|---|---|
| `stage-1-core-mail.md` | 核とメールで一切れ |
| `stage-2-extension-points.md` | 拡張の口を固める。HTTP API・CLI・MCP |
| `stage-3-extensions.md` | 残りの拡張 |
| `stage-4-open.md` | 他人に開く |

## 進め方の要点

- 各段階のファイルにある「完了の条件」を満たしたら、報告を書いて、確認を待たずに次の段階へ進む。
- 迷ったら `02-defaults.md` と `03-design.md` に従って自分で決め、`docs/decisions.md` に記録する。
- 止まるのは、`04-workflow.md` の「止まって確認する場合」だけ。
- 進み具合は `docs/plan/PROGRESS.md` に、段階と受け入れ条件ごとに記録する。作業を再開するときは、まずこのファイルを読む。
