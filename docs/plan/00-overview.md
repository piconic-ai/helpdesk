# helpdesk の全体像

何を作り、何を作らないかを示します。

## helpdesk とは

ユーザーの声を聞き、改善につなげるための道具です。多作の個人開発者が、複数のプロダクトに届く問い合わせを1か所で扱います。自分の Cloudflare アカウントにセルフホストでき、OSS として公開します。

核は「ユーザーと運営が、メールでやりとりできる」ことです。フィードバック受付、ヘルプページ、ヘルプチャット、issue 起票などは、核の上に載る拡張です。同梱する機能も、外部の人が作る拡張と同じ口を使って作ります。自分たちで使えない口は、他人にも使えないためです。

目指す数値は次の4つです。本体は、これらを計算できる出来事を最初から記録します。

| 数値 | 測るもの | 役割 |
|---|---|---|
| A | ユーザーが解決するまでの時間 | 北極星 |
| D | 1回で解決した割合 | 速さを追って雑になっていないかの歯止め |
| F | 1件あたりの運営の作業時間 | 二番手 |
| E | 声が改善に届いた割合 | 「直す」が回っているか |

解決までの時間を縮める手段は3つあります。答える、自分で解決できるようにする、直す、です。もっとも効くのは「直す」で、答える人と直す人が同じである個人開発者の強みです。会話から issue を起こし、直し、声を寄せた人へ知らせるまでを、返信と同じ手軽さで行えるようにします。

誠実さを、機能の判断基準にします。届いたことを必ず伝える。分からないことは分からないと答える。自動の応答に人のふりをさせない。

## 作る範囲

次の4段階を、順に、すべて作ります。順番は優先度ではなく依存の順です。拡張の口が固まる前に拡張を増やすと、口を変えるたびにすべてを直すことになるため、2 を 3 より先に置きます。

1. **核とメールで一切れ**: 窓口アドレスに届いた1通に、運営画面からそのアドレスで返信し、完了にできる。
2. **拡張の口を固める**: 性質の違う拡張を3つ(フォーム受付 API = 入口、issue 起票 = 出口、定型返信 = 操作と画面)、口を通して作る。同時に、操作を CLI と MCP に出す。
3. **残りの拡張**: `stage-3-extensions.md` の拡張をすべて作る。
4. **他人に開く**: セルフホストの手順、設定の検証、拡張の作り方の文書を整える。

## 作らないもの

- 人が常駐するライブチャット、SNS や電話の受付
- 相手向けのポータルとログイン
- SLA と細かい勤務管理
- 一斉配信やマーケティングのメール、新規メールの作成、連絡先管理
- 複数の組織を1つの環境に入れる SaaS 型の運用(1つのデプロイは1つの運営主体のもの)
- ヘルプ記事の版の管理や承認の流れ
- ヘルプチャットでの文章の生成(記事の選択と、確かさの判定だけを行う)
- メールの開封の追跡
