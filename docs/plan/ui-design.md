# UI を DESIGN.md に合わせる

リポジトリのルートに置いた `DESIGN.md` を、画面の唯一の基準にします。既存の画面をすべてこの基準に合わせ、人が画像を見るだけでレビューできる状態にしてください。振る舞いは変えません。

## 守ること

- 変えるのは見た目と HTML の構造だけです。操作、遷移、権限、送信の流れは変えません。既存のテストは、セレクターの追従を除いて書き換えません。
- 色、文字、余白、角丸は、`DESIGN.md` のトークンだけを使います。トークンは CSS カスタムプロパティとして1つのファイルに定義し、名前を `DESIGN.md` のキーと揃えます。
- 部品は `DESIGN.md` の Components にあるものだけを使います。足りない部品が見つかったら、先に `DESIGN.md` に追記し、同じ commit で使います。
- 画面の文言は日本語です。`DESIGN.md` に書かれた文言(状態の名前、内部メモの注記など)は、そのまま使います。
- 層の決まりは変わりません。見た目の変更は pages の層に閉じます。
- BarefootJS の使い方は `pnpm exec bf docs` と `pnpm exec bf guide` で確かめます。

## 作る順番

1. **現状の記録**: 下の「画面の一覧」を Playwright で撮り、`docs/reports/ui/before/` に保存する。画面を再現するための例示データ(未対応・返信待ち・完了・迷惑メール、送信失敗、承認待ち、内部メモ、HTML メール、長い件名、日本語の長文)を、1つのシード用スクリプトにまとめる。
2. **トークンと土台**: トークンの CSS、文字の基準、フォーカスの表示、ボタン、入力欄、バッジ、バナー。
3. **枠**: サイドバー、ページの見出し、絞り込み。
4. **会話の一覧**。
5. **会話の画面**: メッセージ3種、送信の状態、添付、右のパネル。
6. **返信欄**: 返信と内部メモの切り替え、差出人と宛先の表示、送信中と失敗。
7. **設定と拡張の画面**: フォーム、エラー、削除の確認。
8. **公開の画面**: ヘルプページ、フィードバック、ヘルプチャット。
9. **仕上げ**: 空の状態、読み込み中、エラー、幅 375px・1024px・1440px での崩れ、キーボードだけでの操作。

4 と 5 を終えた時点で `docs/reports/ui/` に途中の比較を出し、そのまま先へ進みます。

## 画面の一覧

状態ごとに撮ります。幅は 1440px を基本とし、* を付けたものは 375px も撮ります。

- 会話の一覧: 未対応が複数ある状態*、空の状態、絞り込み中、送信失敗を含む状態
- 会話の画面: 受信だけ*、返信済み、内部メモあり、送信失敗、承認待ち、HTML メール、添付あり
- 返信欄: 空、入力中、内部メモに切り替え*、送信中、送信失敗
- 設定: プロダクトと窓口、運営者、拡張の一覧、入力エラー、削除の確認
- 拡張: 有効にしたものごとに、主な画面を1枚
- 公開: ヘルプ記事*、フィードバックの入力と完了*、ヘルプチャットの入力・記事の提示・問い合わせの受付*

## 自動で確かめること

- **トークン以外の値が無いこと**: pages と CSS の中に、トークンの定義ファイル以外で色の直書き(hex、rgb、hsl)が無いことを検査するテスト。余白と角丸も、尺度に無い値を検査する。
- **コントラスト**: `DESIGN.md` の文字色と背景色の組が WCAG AA を満たすことを、トークンの値から計算するテスト。無効なボタン(`button-primary-disabled`)は対象から外す。
- **アクセシビリティ**: axe で、画面の一覧のすべての状態を検査する。違反はゼロにする。
- **キーボード**: 一覧から会話を開き、返信を書いて送信し、完了にするまでを、キーボードだけで通す Playwright のテスト。
- **1画面に主ボタンは1つ**: 画面の一覧の各状態で、主ボタンが2つ以上無いことを検査する。
- **見た目の回帰**: 画面の一覧を Playwright のスクリーンショット比較に登録する。時刻と乱数は固定する。
- **内部メモの区別**: 内部メモの表示と、内部メモに切り替えた返信欄に、注記の文言があることを検査する。

`docs/plan/05-verification.md` のコマンドは、すべて通る状態を保ちます。

## レビュー用の成果物

人が1ページを上から見るだけで判断できるものを作ります。

- `docs/reports/ui/index.html`: 画面の一覧の順に、変更前と変更後の画像を左右に並べる。画面ごとに、変えた点を1〜3行で添える。
- `docs/reports/ui/README.md`: 自動で確かめたこと、`DESIGN.md` に追記した部品、判断に迷って自分で決めたこと、人の目で見てほしい点。

## 完了の条件

- 画面の一覧のすべての状態が、`DESIGN.md` の部品とトークンだけで組まれている。
- 「自動で確かめること」のテストがすべてあり、通っている。
- レビュー用の成果物が揃っている。
- 振る舞いのテストが、変更前と同じ数だけ通っている。
