# 既定値

決まっていない事項を、どの値で実装するかを示します。

## 既定値

決まっていない事項は、次の既定値で実装します。どれも設定か1ファイルの差し替えで変えられる形にし、`docs/decisions.md` に「既定値として実装」と書いてください。表に無い事項は、同じ考え方で自分で決めて記録します。

| 事項 | 既定値 |
|---|---|
| 問い合わせ番号 | デプロイ全体の通し番号。表示は `#123`、件名には `[#123]` を添える |
| 運営画面の認証 | Cloudflare Access の JWT を検証する |
| 運営者の登録 | Access で認証されたアドレスを、初回アクセス時に登録する。最初の1人が管理者 |
| 権限 | 管理者と担当者の2種類。管理者だけが設定・運営者・保存期間・拡張の有効化を扱う |
| ローカルでの認証 | 環境変数で明示したときだけ、固定の開発用運営者として扱う。本番の設定で有効なら起動時にエラー |
| CLI とエージェントの認証 | 運営者が発行する API トークン。ハッシュだけを D1 に保存し、権限の範囲と、代理する運営者を持つ |
| MCP | 同じ Worker の上の HTTP の入口。実装の手段は、MCP と Cloudflare の現在の公式ドキュメントを読んで選ぶ |
| 拡張の束ね方 | `helpdesk.config.ts` に書いた拡張を静的に import し、1つの Worker にまとめる。実行時に外部のコードは読み込まない |
| 迷惑メールの判定 | 受信時の認証結果と簡単な規則による隔離。隔離したものは一覧から確認して戻せる |
| 通知 | Webhook(Slack と Discord が受け取れる形)。運営者へのメール通知は設定で追加 |
| 自動の受付返信 | 新しい会話の最初の1通にだけ送る。自動送信メールとバウンスには送らない。文面に自動送信であることを明記する |
| ヘルプ記事の置き場 | D1。運営画面で Markdown で書く |
| ヘルプチャットの判断 | Workers AI。`judge-client.ts` の1ファイルに閉じ込める。使うモデルは現在の公式ドキュメントで選ぶ |
| issue の起票先 | GitHub。プロダクトごとにリポジトリを設定する |
| issue に載せる内容 | 運営者が書いた要約と問い合わせ番号だけ。相手の名前・アドレス・本文は載せない。起票の前に人が内容を確認する |
| 書き出し | JSON Lines。名前とアドレスは既定で伏せる |
| 検索 | D1 の全文検索が使えればそれを使い、使えなければ件名・差出人・本文の部分一致 |
| 受信の大きさの上限 | Email Routing の上限に従う。超えたものは原文を残して運営者に知らせる |
| 保存期間 | 既定では自動で削除しない。期間を設定したときだけ削除する。相手単位の削除は常に使える |
| F の測り方 | 会話を開いてから返信を送るまでの時間を、画面から出来事として記録する。CLI と MCP からの作業時間は測らない |
| ライセンス | LICENSE は置かない(未決) |
| 実行環境 | Node.js 24、pnpm。slide の CI と同じ版 |
