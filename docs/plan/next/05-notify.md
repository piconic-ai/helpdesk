# 運営者への知らせ(拡張 `notify`)

問い合わせが届いたことや、承認を待つ下書きがあることを、運営者がふだん使っている場所に知らせます。対象は Slack と Discord です。知らせるだけで、そこから返信はしません。返信は運営画面で行います。

## 核に足すもの

- 核は、出来事(会話の受付、相手からの返事、担当者の変更、承認待ちの発生、送信の失敗、締切の超過)を、拡張が受け取れる形で出す。すでにある出来事の仕組みを使い、足りない種類だけを足す。核は、Slack も Discord も知らない。

## 決めること

- **送り先。** プロジェクトごとに、送り先を複数登録できる。送り先は、Slack または Discord の Incoming Webhook の URL である。URL は秘密として保存し、画面には末尾の数文字だけを出す。登録できるのはプロジェクトの管理者である。
- **知らせる出来事。** 送り先ごとに選ぶ。初めは「新しい問い合わせ」「承認待ち」「送信の失敗」を選んだ状態にする。
- **絞り込み。** ラベル、担当者がいないものだけ、などの条件を付けられる。
- **まとめる。** 同じ会話の出来事が短い時間に続いたら、1通にまとめる。1分あたりの上限を超えたら、「ほか N件」として1通にする。

## 知らせの内容

- プロジェクト名、問い合わせ番号、件名、状態、担当者、運営画面へのリンクを載せる。
- **相手の名前、メールアドレス、本文は、初めの設定では載せない。** 送り先ごとに「件名と名前まで」「本文の最初の100字まで」を選べる。外の場所に個人の情報が残るため、選ぶ画面にその旨を書く。
- 内部メモの本文は、どの設定でも載せない。

## 守ること

- 送信は Queue を通す。失敗したら間隔を空けて3回までやり直す。続けて失敗した送り先は止め、設定の画面と管理者への知らせに出す。
- 知らせの送信の失敗が、会話の受付や返信を止めない。
- 設定の画面に「試しに送る」がある。
- 送った記録(いつ、どの出来事、成否)を、送り先ごとに直近100件まで見られる。

## 型

```ts
type Destination = { id: DestinationId; product: ProductId; kind: 'slack' | 'discord'; name: string; events: EventKind[]; filter: Filter; detail: 'minimal' | 'subject' | 'excerpt'; state: { kind: 'active' } | { kind: 'stopped'; reason: string; at: Instant } }
function render(event: DomainEvent, dest: Destination): Result<Payload, Skipped>
function batch(events: DomainEvent[], window: Duration, limit: number): Batch[]
```

`render` と `batch` は純粋関数にする。Slack と Discord の違いは `render` の中だけに置く。送り先の種類を足すときは、`kind` と `render` の分岐を足すだけで済むようにする。

## 自動で確かめること

- `detail` が `minimal` のとき、名前、メールアドレス、本文が出力に含まれないこと(性質のテスト)。
- 内部メモの本文が、どの設定でも含まれないこと。
- まとめと上限。
- 属していないプロジェクトの送り先が、見えず、変えられないこと。
- 送信の失敗、やり直し、停止。
- 模擬の受け口を使った通しのテスト。

## 完了の条件

- 送り先の登録・編集・停止・試し送り、送った記録の画面がある。
- デモの環境に、模擬の受け口と、届いた知らせを見られる画面がある。
- 検査が通っている。
- ハンズオンに、Slack に知らせを出す章がある。
