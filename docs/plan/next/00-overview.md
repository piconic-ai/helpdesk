# 次の段階の全体像

この段階では、いまの画面に残っている問題を直したうえで、多くの相手と、同じ段取りで、一人ずつやりとりを進める場面を扱えるようにします。スピーカーの募集やスポンサーの募集が、その代表です。送るのは一斉の配信ではありません。相手ごとに会話があり、返事はその人との会話に入ります。まとめるのは、宛先を選ぶこと、同じ連絡を始めること、全員の進み具合を見渡すことです。

## 読む順と、作る順

| 順 | ファイル | 内容 | 種類 |
|---|---|---|---|
| 1 | `01-fixes.md` | いまの画面に残っている問題を直す。送信の待ち時間、線でたどる会話の詳細、定型文の提示を含む | 核 |
| 2 | `02-projects-and-roles.md` | 呼び名を「プロジェクト」にし、プロジェクトごとの担当者と権限を作る。プロジェクトが増えても崩れない画面にする | 核 |
| 3 | `03-outreach.md` | 相手をまとめ、個別の連絡を同時に始める | 拡張 `outreach` |
| 4 | `04-flows.md` | 決まった段取りの受付と、進み具合の管理 | 拡張 `flows` |
| 5 | `05-notify.md` | Slack と Discord に、運営者への知らせを出す | 拡張 `notify` |

3 は 2 の上に、4 は 3 の上に作ります。5 は 2 だけに依存します。これまでの決まり(層、型、承認、`DESIGN.md`、振る舞いの決まり、余白の仕組み)は変えません。この段階の文書と、これまでの文書が食い違うときは、この段階の文書に従います。

## 進め方

- `feat/helpdesk-daily-workflows` を main に取り込み、以後は main に直接積む。利用者も、ほかの開発者もまだいないため、プルリクエストは作らない。公開するとき、またはほかの人が使い始めるときに、プルリクエストでの進め方に切り替える。
- main への push のたびに、`docs/plan/05-verification.md` のコマンドが CI で走るようにする。落ちたら、次の作業の前に直す。
- 区切り(`01` から `05` のそれぞれの完了)ごとに、タグを打つ。名前は `checkpoint/next-01`、`checkpoint/next-02` のようにする。
- コミットは、1つの変更で1つにする。検査が通る状態でコミットする。
- 1つのファイルの「完了の条件」を満たしてから、次のファイルに進む。途中で止まったときは、最後に打ったタグの次のファイルから再開する。

## あわせて反映する決定

機能追加とは別に、次の3つが決まっています。`02-projects-and-roles.md` に着手する前に反映します。

- **問い合わせ番号の形式。** `#1234` をやめ、プロジェクトごとの接頭辞を付けた `SLD-1234` の形にする。GitHub が `#1234` を issue や PR への参照として扱うためである。接頭辞はプロジェクトの設定で決める(英大文字2〜5字、重複不可)。通し番号は、デプロイ全体で1本にする。件名は `[SLD-1234]` とし、画面、issue の本文、知らせの文面も揃える。会話をほかのプロジェクトへ移すと、数字はそのままで接頭辞が変わる。古い接頭辞や `[#123]` の件名への返信も、数字で同じ会話に入る。
- **公開の issue に載せる内容。** 運営画面の URL を載せない。起票の本文は、要約と問い合わせ番号だけにする。紐づけのときに、issue へコメントを投稿しない。
- **ライセンス。** MIT にする。`LICENSE` を追加し、著作権者は依頼者に確認した個人名にする。`package.json` と README の表記、依存パッケージのライセンスとの矛盾が無いことも確かめる。


## 指針の改訂

`docs/product.md` を、次のように改めます。

- **利用場面に加える。** 「運営者が、複数の相手と、同じ段取りで個別にやりとりを進める。例: カンファレンスのスピーカーやスポンサーとの連絡、ベータ版の参加者との連絡、障害の影響を受けた人への個別の連絡」
- **「プロダクト」を「プロジェクト」と呼び替える。** 窓口と担当者をまとめる単位を、画面、メール、公開のページ、文書で「プロジェクト」と呼ぶ。ソフトウェアの製品のほか、カンファレンスの1回の開催やコミュニティも、1つのプロジェクトとして登録できる。呼び名は文言の定義の1か所から引き、画面ごとに直接書かない。コードの中の名前(`product`、`ProductId`)、URL の `product=`、埋め込みの `data-product` は変えない。GitHub の Projects と紛れる場所(課題の画面)では、「GitHub の」を付けて区別する。
- **「作らないこと」を書き換える。** 「一斉配信やマーケティングのメール」を、「宣伝や購読のための一斉配信。関係のある相手への連絡を、個別の会話としてまとめて始めることはできる」にする。「新規メールの作成や連絡先管理」を、「汎用のメールソフトや顧客管理。運営から会話を始めること、相手に目印を付けてまとめることはできる」にする。
- **ワークフローに W6 を加える。** 「W6 まとめて進める: 相手を選ぶ → 同じ連絡を個別に始める → 返事を一人ずつ受ける → 段階を進める → 全員の進み具合を見渡す」
