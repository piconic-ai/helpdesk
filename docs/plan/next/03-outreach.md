# 相手をまとめ、個別の連絡を同時に始める(拡張 `outreach`)

## 核に足すもの

運営の側から会話を始められるようにします。いまの核は、相手から届いた連絡で会話が始まることだけを想定しています。

- 会話の始まり方に `operator`(運営から始めた)を加える。核の型の変更なので、理由を `docs/decisions.md` に書く。
- 運営から始めた会話は、最初のメッセージが返信(送信)で、状態は「返信待ち」から始まる。相手が返事をすると「未対応」になる。以降は、通常の会話と同じ。
- 画面からは、相手を1人選んで会話を始められる(受信箱の「新しい会話」)。拡張は、核の「会話を始める」手続きを通して、これを使う。

## 相手に目印を付ける

- 相手(連絡先)に、プロジェクトごとの「目印」を付けられる。例: スピーカー、スポンサー、ベータ参加者。目印は、会話のラベルとは別に持つ。相手についての分類だからである。
- 相手ごとに、項目(会社名、役職、発表の題など)を持てる。項目の種類は、プロジェクトごとに決める。
- 「相手」の一覧を、サイドバーに加える。相手を押すと、その人の項目、目印、会話の一覧が見える。
- 相手の取り込み: CSV から、名前・アドレス・目印・項目を取り込める。取り込む前に、件数と、重複、誤ったアドレスを示す。

## 宛先リスト

- 相手を選ぶ条件を、名前を付けて保存できる。条件は、目印、項目の値、`04-flows.md` の段階、最後のやりとりからの日数の組み合わせ。
- 宛先リストは、開くたびに条件で選び直す。手で選んだ固定の一覧として保存することもできる。
- 一覧に、いま何人が当てはまるかを出す。

## まとめて連絡する

1. 宛先リストか、相手の一覧で選んだ人を宛先にする。
2. 件名と本文を書く。相手の名前や項目を差し込める。定型文から始められる。ファイルを添えられる。
3. **確認の画面**で、次を示す。宛先の人数、差出人、差し込み後の文面の見本(相手を切り替えて見られる)、差し込む項目が空の相手、過去に配送に失敗した相手、すでに同じ連絡を受け取った相手。
4. 自分宛てに試しに送れる。
5. プロジェクトの管理者が承認すると、送信が始まる。担当者が作ったものは、承認待ちで止まる。
6. 相手ごとに、会話が1つ始まる(その連絡についての進行中の会話があれば、そこに足す)。会話には、どの連絡から始まったかが残る。
7. 進み具合の画面で、送信済み、失敗、返事あり、返事なしの人数と一覧を見られる。返事のない人だけを選んで、もう一度連絡できる。

## 相手の側に、複数の人がいる場合

スポンサーは、1社に担当者が複数いて、誰に送るかは企業の希望によります。

- 1つの会話に、相手を複数人登録できる。人ごとに「宛先」「写し」「送らない」を選べる。
- 登録した誰から返事が来ても、同じ会話に入る。登録していない人からの返事は、これまでどおり別の会話にし、会話の画面で「この会話に加える」を選べる。
- 相手を、会社などのまとまりで束ねられる。まとまりに目印や項目を付けられる。
- これは核の変更になる。会話の相手を1人としている型を改め、理由を `docs/decisions.md` に書く。差出人の確認(他人の会話に割り込めない)の決まりは、登録した相手全員に対して保つ。

## 窓口の外で連絡した記録

返事が来ない相手を、SNS やチャットで追いかけることがあります。その経緯が、ほかの運営メンバーに見えるようにします。

- 会話に、「窓口の外で連絡した」を、手段(SNS、チャット、電話、対面)と一言を添えて、1回の操作で残せる。内部メモの一種として扱い、相手には送られない。
- 進み具合の表の「最後のやりとり」に、この記録も含める。

## 課題の知らせに使う

課題を直したあとの知らせも、この仕組みに載せます。

- 課題の詳細で、文面を一度書き、紐づく声の主を宛先にして、確認と承認を1回で行える。何を直したかが相手に伝わるよう、文面の初期値に課題の題を入れる。
- 下書きを作ったあとの「知らせる待ち」には、「承認待ち」と件数を出し、確認の画面へ進める。

## 守ること

- **宣伝には使わない。** 拡張の説明と、確認の画面に明記する。開封の追跡、リンクの計測は作らない。
- **配信ではなく、会話である。** 相手に届くメールは、1人に宛てた通常のメールにする。ほかの宛先は見えない。返事は、その人との会話に入る。
- **人が承認する。** 承認の記録は、会話ごとの返信の承認として残る(承認者 = 承認した管理者)。
- **承認のあと、送り始めるまでに待ち時間を置く。** 既定は5分。そのあいだは、全体を取り消せる。送り始めたあとも、まだ送っていない相手の分は止められる。待ち時間と、止めたときに何人に送り済みかを、確認の画面と進み具合の画面に出す。仕組みは `01-fixes.md` の送信の待ち時間と同じものを使う。
- **一度に送れる人数に上限を置く。** 既定は200人。プロジェクトごとに変えられる。
- **ゆっくり送る。** 送信の速さに上限を置く。失敗の割合が一定を超えたら自動で止め、管理者に知らせる。窓口のドメインの評価を守るためである。
- **配送に失敗した相手は、次から宛先の候補で印を付ける。**
- **相手が連絡を望まないと伝えてきたら、その相手に「連絡しない」の印を付けられる。** 印のある相手は、まとめての連絡の宛先から外れる。
- **Cloudflare の送信の上限と料金を、作る前に公式のドキュメントで確かめる。** 確認の画面に、今月の送信数の目安を出す。

## 型

```ts
type Outreach =
  | { kind: 'draft'; ... }
  | { kind: 'awaiting_approval'; requestedBy: OperatorId; ... }
  | { kind: 'sending'; approvedBy: OperatorId; startedAt: Instant; ... }
  | { kind: 'paused'; reason: PauseReason; ... }       // failure rate exceeded, or paused by a manager
  | { kind: 'finished'; finishedAt: Instant; ... }

type RecipientState =
  | { kind: 'pending' }
  | { kind: 'skipped'; reason: 'do_not_contact' | 'missing_field' | 'duplicate' | 'invalid_address' }
  | { kind: 'sent'; conversation: ConversationNumber }
  | { kind: 'failed'; reason: SendFailure }
```

宛先の決定(条件から相手を選ぶ、除外する理由を付ける)と、差し込みは、純粋な関数にします。

## 自動で確かめること

- 条件と相手の例示から、選ばれる相手と、除外の理由が決まること。
- 差し込み: 項目が空、項目に記号や改行、相手の名前に HTML、を含む例。
- 承認の前に、1通も送られないこと。担当者だけでは送信に至らないこと。
- 相手ごとに会話ができ、返事がその会話に入り、ほかの相手の会話に入らないこと。
- 同じ処理が2回走っても、同じ相手に2通送らないこと。
- 上限を超える人数で、送信を始められないこと。失敗の割合で止まること。
- 「連絡しない」の相手が、宛先から外れること。
- `02-projects-and-roles.md` の権限: 属していないプロジェクトの相手と宛先リストが見えないこと。

## 完了の条件

- 相手の一覧、目印、項目、取り込み、宛先リスト、まとめての連絡、進み具合の画面がある。
- 検査が通っている。
- ハンズオンに、目印を付ける → 宛先リストを作る → 連絡を承認して送る → 返事を個別に受ける、の章がある。
