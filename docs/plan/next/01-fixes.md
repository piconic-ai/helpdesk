# 先に直すこと

いまの画面をワークフローの順に操作して見つかった点です。機能追加の前に直します。相手に届く文面と、数字の正しさに関わるものを先にします。

## 相手に届く文面

- **課題の知らせ。** 直したことを知らせる文面が、どの課題にも同じ定型文になっている。契約更新の質問に「問題の修正が完了しました」と届く。下書きには、課題の題と、相手の問い合わせの件名を入れ、何が変わったかを1文で書く。相手の問い合わせが不具合の報告か、要望か、質問かで、書き出しを変える。
- **解決アンケート。** 完了のあとに自動で送る文面が英語になっている。窓口の言語に合わせ、日本語の文面を用意する。文面はプロジェクトの設定で変えられるようにする。
- **定型文。** 同梱の定型文が英語の1件だけである。日本語の見本を3件(受付の知らせ、確認中の知らせ、解決の知らせ)にする。

## 数字の正しさ

- **当日の集計。** 対応状況の集計に、当日に完了した会話が入っていない。完了が2件あるのに、集計は1件で、期間の終わりが前日になっていた。「過去7日」「過去30日」は、いまの時刻までを含める。日付の境目は、運営者の時間帯で決める。期間の計算は純粋関数にし、境目(当日、月の変わり目、時間帯の違い)をテストする。

## W1 問い合わせに答える

- **合いそうな定型文を示す。** 返信の入力欄の上に、問い合わせの内容に合う定型文を3件まで出す。押すと、宛名などを差し込んだ文が入力欄に入る。入れた文は、送る前に直せる。入力欄にすでに文があるときは、置き換えずにカーソルの位置へ入れる。選び方は、記事の提示(`ux-fixes-8.md`)と同じにする。そのプロジェクトの定型文を候補にし、Clef の `noul` で「この定型文は、この問い合わせへの返信に使えるか」を判定し、0.6 以上のものを確率の高い順に出す。合うものが無ければ、何も出さない。判定は会話を開いたときに1回だけ行い、相手から新しいメッセージが届くまで結果を使い回す。Clef を使えないときは、ラベルと件名の一致で選ぶ。示した定型文、選ばれた定型文、送る前に直された割合を記録し、定型文の一覧に「示した回数、使われた回数」を出す。使われない定型文を見直せるようにするためである。合う記事の提示と並ぶときは、1つの帯に「記事」「定型文」としてまとめ、入力欄の上に2つの帯を重ねない。
- 一覧で、差出人の名前が長いと4行に折れる。名前は2行までで省略し、全文はツールチップと読み上げ用の名前に入れる。プロジェクト名は省略しない。

## 送ったあと、しばらく取り消せるようにする

送る操作をしてから実際に送るまでに待ち時間を置き、そのあいだは取り消せるようにします。送り間違いに気づくのは、送った直後が多いためです。

- **待ち時間。** 既定は10秒。運営者ごとに、10秒、30秒、1分、5分から選べる。プロジェクトの管理者は、そのプロジェクトの下限を決められる(例: このプロジェクトでは1分以上)。長くするほど、相手に届くのが遅れる。設定の画面にその旨を書く。
- **待っているあいだの見え方。** 会話の線の上に「送信予定 0:05 まで」と残りの時間を出し、「今すぐ送る」「取り消す」を置く。トーストにも同じ2つを出すが、トーストが消えたあとも、会話の画面から取り消せる。一覧の行にも「送信予定」の印を出す。
- **取り消したとき。** 文は、返信の入力欄に下書きとして戻る。「送信して完了」で送っていたら、完了も元の状態に戻す。
- **実際に送られてから起きること。** 状態の変化(返信待ち、完了)は、送る操作の時点で画面に反映してよい。ただし、相手に届くもの(完了のあとの解決アンケート、課題への知らせ)と、集計の「返信した時刻」は、実際に送られた時刻を使う。
- **待っているあいだに相手から新しいメッセージが届いたら、送信を止める。** 行き違いの返信を防ぐためである。文は下書きに戻し、送った運営者に「相手から新しいメッセージが届いたため、送信を止めました」と知らせる。
- **承認して送る文にも、同じ待ち時間を置く。** エージェントや拡張が作った下書きを承認したあとも、取り消せる。
- **作り方。** 送る操作で、D1 に送信の予定(送る時刻、状態)を書き、Queue に遅延を付けて積む。取り消しは、Queue から消さず、D1 の状態を変える。Queue から届いたときに D1 の状態と送る時刻を見て、送ってよいときだけ送る。同じ予定が2回届いても、1回しか送らない。Queue の遅延の上限は、作る前に Cloudflare の公式のドキュメントで確かめる。
- **純粋関数にするもの。** 「いま送ってよいか」の判定(送る時刻、状態、あとから届いた相手のメッセージの有無から決める)と、待ち時間の決定(運営者の設定とプロジェクトの下限から決める)。

```ts
type Outgoing =
  | { kind: 'scheduled'; sendAt: Instant; by: OperatorId }
  | { kind: 'cancelled'; at: Instant; by: OperatorId }
  | { kind: 'held'; reason: 'customer_replied'; at: Instant }
  | { kind: 'sent'; at: Instant }
  | { kind: 'failed'; at: Instant; reason: string }
function decideSend(o: Outgoing, now: Instant, lastInboundAt: Instant | null): 'send' | 'wait' | 'skip' | 'hold'
function sendDelay(operator: Duration, projectMin: Duration | null): Duration
```

確かめること: 待ち時間の前に送られないこと。取り消したものが送られないこと。取り消しと送信が同時に起きても、どちらか一方だけになること。2回届いても1回しか送らないこと。相手のメッセージが先に届いたら止まること。アンケートと知らせが、実際の送信のあとに出ること。

## 会話の詳細を、1本の線でたどれるようにする

会話の詳細は、要素が多く、どの順に読めばよいか、何がいつ起きたかが追いにくい。上から下へ1本の線をたどれば、何が起きて、いま何をすべきかが分かる形にする。

- **線は1本。** 画面の左に縦の線を引き、メッセージ、内部メモ、下書き、出来事(受付、担当の変更、状態の変化、ラベル、課題の紐づけ、送信の失敗)を、同じ線の上に時刻順で並べる。関連情報のパネルの「操作履歴」に分かれていた出来事も、この線に入れる。
- **重さは3段。** 相手と運営のメッセージはカードにする。内部メモは、色を変えたカードにする。出来事は、カードにせず1行にする。短い時間に続いた同じ種類の出来事は、最後の状態の1行にまとめる。
- **線の印で、誰のものかを示す。** 相手は白抜きの丸、運営は塗った丸、出来事は小さい点にする。色だけに頼らず、カードの見出しにも「相手」「返信」「内部メモ」と書く。
- **線の終わりが「次にすること」。** 線のいちばん下に、いまやることを1つだけ書く。未対応なら「返信する(N時間待たせています)」、承認待ちの下書きがあれば「下書きを確認して送る」、返信待ちなら「相手の返事を待っています」、完了なら「完了しました。再開するには返信を書きます」。返信の入力欄、合いそうな定型文と記事、承認待ちの下書きは、ここに置く。
- **上の帯は変えない。** 件名、番号、プロジェクト、状態、担当者、ラベルと、操作のボタンは、これまでどおり上部の同じ位置に置く。線は、その下から始める。
- **長い会話。** メッセージが10件を超えたら、最初の1件と直近の5件を開き、あいだは「N件のやりとり」として畳む。畳んだ部分も線はつながって見える。開くと、その場に展開する。出来事だけを隠す切り替えを付ける。
- **幅が狭いとき。** 線と印は残し、カードの左の余白を詰める。線を消さない。
- 何をいつ表示するかの組み立て(並べる、まとめる、畳む、次にすることを決める)は純粋関数にし、画面から分ける。

## W2 声を受け止める

- フィードバックの詳細で、操作のボタンが「← 受信箱」より上の行にある。会話の詳細と同じ帯、同じ位置に置く。
- フィードバックの一覧から開いたとき、戻る先の文言を「← フィードバック」にする。ほかの一覧から開いたときも、来た一覧の名前にする。
- 公開のフォーム(フィードバック、問い合わせ、ヘルプチャット)の入力欄に、見出しと結びついた名前が無い。`label` と入力欄を結びつける。

## W3 自分で解決してもらう

- 記事の提示が題だけである。題の下に、記事の最初の1〜2文を添える。

## W4 改善につなげる

- 下書きが承認待ちの課題にも、一覧に「下書きを作る」が出る。承認待ちがあるときは「承認待ち N件を確認する」にし、押すと課題の詳細に移る。
- 承認が会話ごとになっている。課題の詳細に、承認待ちの下書きを相手ごとに並べ、文面を読んだうえで、選んだものをまとめて承認できるようにする。1件ずつ文面を直せることは保つ。
- 会話に合いそうな課題があるとき、関連情報のパネルを開く前に分かるようにする。題と本文の一致で候補を1件まで出す。

## W5 場を整える

## 画面の崩れ

- 畳んだサイドバーで、「声の集計」「対応状況の集計」だけ文字が出る。ほかの項目と同じく、アイコンだけにし、名前はツールチップに出す。
- 拡張の管理で、幅が狭いとカードの題が3行に折れる。題は折り返さず、カードの最小の幅を決め、入らなければ1列にする。
- 一覧で選択中の帯が2段になる。件数、選択の解除、操作を1段に収める。入らない操作は「その他」にまとめる。
