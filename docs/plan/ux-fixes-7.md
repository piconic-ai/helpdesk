# ヘルプチャットを、1行のスクリプトで埋め込めるようにする

ヘルプチャットは、いまは独立したページのフォームです。ユーザーが困るのはプロダクトを使っている最中なので、プロダクトの画面の隅から、その場で開けるようにします。あわせて、中身を、やりとりが積み重なる形に作り直します。

置き場所は `docs/plan/ux-fixes-7.md` です。`ux-fixes-5.md` と `ux-fixes-6.md` を済ませてから着手します。

## 1. 埋め込み方

プロダクトの HTML に、次の1行を足すだけで動くようにします。

```html
<script src="https://help.example.com/widget.js" data-product="slide" async></script>
```

設定は、スクリプトの属性で行います。

| 属性 | 意味 | 既定 |
|---|---|---|
| `data-product` | プロダクトの ID。必須 | — |
| `data-position` | ボタンの位置。`bottom-right` か `bottom-left` | `bottom-right` |
| `data-label` | ボタンの文言 | 「ヘルプ」 |
| `data-launcher` | `none` にすると、ボタンを出さない。プロダクト側の要素に `data-helpdesk-open` を付けると、それが開くボタンになる | ボタンを出す |
| `data-lang` | 表示の言語 | ページの言語 |

プロダクトのコードから操作するための、小さな API も用意します。

```js
window.Helpdesk.open()      // open the panel
window.Helpdesk.close()
window.Helpdesk.prefill({ email: 'user@example.com' })  // fills the contact field; the user can edit it
```

`prefill` で渡された値は、入力欄の初期値にするだけです。本人であることの証明としては扱いません。誰でも任意の値を渡せるためです。

## 2. 仕組み

- **スクリプトは、ボタンと枠を作るだけにする。** `widget.js` は依存を持たず、数 KB に収める。ボタンと、中身を表示する iframe を作る。iframe は、最初に開いたときに読み込む。
- **中身は iframe の中に置く。** プロダクトの CSS と互いに影響しない。プロダクトのページから、やりとりの内容を読めない。
- **埋め込める先を、プロダクトごとに登録する。** 運営画面で、埋め込み先のオリジンを登録する。iframe の応答に、登録したオリジンだけを許す `Content-Security-Policy: frame-ancestors` を付ける。登録の無いオリジンには表示されない。
- **スクリプトと iframe のやりとりは、最小限にする。** `postMessage` で送るのは、開く・閉じる・高さ・初期値だけ。受け取る側は、送り元のオリジンを必ず確かめる。
- **どのページから開いたかを添える。** 問い合わせになったとき、開いたページのオリジンとパスを、会話の関連情報に残す。原因がどの画面にあるかを知る手がかりになる。クエリ文字列とハッシュは、個人の情報を含みうるので送らない。
- **既存の守りを通す。** 公開キー、回数制限、Turnstile(設定したとき)は、独立したページと同じものを使う。
- **`widget.js` の URL は変えない。** 中身を更新しても、埋め込んだ側の書き換えが要らないようにする。キャッシュの期間は短めにする。

いまの「埋め込みコード」は、この方式に置き換えます。独立したページ(`/help/chat/<product>`)は、同じ中身を1ページとして表示するものとして残します。

## 3. 中身を、やりとりが積み重なる形にする

文章を生成しない方針は変えません。形だけを対話にします。

```
┌─────────────────────────────┐
│ [icon] Slide のヘルプ         × │
├─────────────────────────────┤
│ 困っていることを書いてください。 │
│ 合うヘルプ記事を自動で探します。 │
│ 見つからなければ、そのまま      │
│ 問い合わせとして受け付けます。   │
│                               │
│            領収書を発行したい ▸ │
│                               │
│ 関連する記事                   │
│ ・領収書を発行する             │
│                               │
│ [解決した] [解決しなかった]     │
├─────────────────────────────┤
│ 質問を入力…              [送る] │
├─────────────────────────────┤
│ ヘルプ記事の一覧 ・ ご意見を送る │
└─────────────────────────────┘
```

決まり:

- **最初に、何が起きるかを伝える。** 自動で記事を探すこと、人が読むのは問い合わせになったあとであることを、最初の表示で示す。人の名前や顔を出さない。入力中を装う表示を出さない。
- **書いた質問と、返ってきた結果が、上から順に残る。** 質問を重ねても、前のやりとりが消えない。
- **記事は、枠の中で読める。** 記事を押すと、枠の中で本文を表示し、戻れる。新しいタブで開く操作も添える。
- **結果のあとに、必ず2つの出口を置く。** 「解決した」と「解決しなかった」。「解決した」は、記事で解決した出来事として記録する。「解決しなかった」は、連絡先を尋ね、これまでの質問をまとめて問い合わせにし、番号を返す。
- **合う記事が無いときは、探したことを伝えたうえで、連絡先を尋ねる。** 黙って問い合わせにしない。
- **受け付けたあとを伝える。** 番号、返信が届く宛先、返信の目安(設定されている場合)。
- **下部に、ほかの入口を置く。** ヘルプ記事の一覧と、返信不要のご意見。フィードバックと問い合わせフォームの拡張が有効なときだけ出す。
- **閉じても、同じページを見ている間は内容を保つ。** 入力の途中で閉じても、開き直せば続きから始められる。保存先はメモリだけにし、ブラウザに残さない。
- **見出しに、プロダクトのアイコンと名前を出す。**

## 4. 見た目と操作

- 開くボタンは、角の丸い小さなボタン。色は `DESIGN.md` の主ボタンと同じにし、プロダクトの画面の上で埋もれないよう、影を付ける。
- パネルは、幅 360px、高さは内容に合わせ、画面の高さの 80% まで。幅 480px 未満の画面では、全画面で開く。
- 開いたら入力欄にフォーカスを移す。Esc で閉じる。閉じたら、開いたボタンにフォーカスを戻す。キーボードだけで、すべての操作に届く。
- ボタンとパネルに、読み上げ用の名前と役割を付ける。
- プロダクトの画面の重なりの順に負けないよう、いちばん手前に出す。プロダクト側の要素を覆い続けないよう、閉じたときはボタンだけにする。

## 5. 運営画面

「拡張の管理」→「ヘルプチャット」の設定に、次を置きます。

- プロダクトごとの、埋め込み用の1行。押すと写せる。
- 埋め込み先のオリジンの登録と削除。
- ボタンの位置と文言の設定。設定に合わせて、埋め込み用の1行が変わる。
- 実際の見え方の確認。設定の画面の中に、埋め込んだ状態の見本を表示する。
- プロダクトが CSP を使っている場合に、許可が必要な項目(`script-src` と `frame-src` に helpdesk のオリジン)の案内。
- 返信の目安と、最初の説明文の編集。

## 6. 文書

`docs/dev/embedding.md` に、埋め込み方、属性、API、CSP の設定、`prefill` が本人の証明にならないこと、開いたページの情報として何を送るかを書きます。README からリンクします。

## 自動で確かめること

開発用に、helpdesk とは別のオリジン(別のポート)で動く見本のページを用意し、そこにスクリプトを埋め込んで確かめます。

- 1行を足すと、ボタンが出て、押すとパネルが開く。
- 質問 → 記事の提示 → 「解決した」で、記事で解決した出来事が残る。
- 質問 → 記事の提示 → 「解決しなかった」→ 連絡先 → 番号が返り、運営の未対応に、質問の文と開いたページのパスと一緒に出る。
- 合う記事が無い質問で、探したことが伝えられ、連絡先を尋ねられる。
- 登録していないオリジンのページでは、パネルの中身が表示されない。
- 見本のページの CSS(すべての要素に強い指定を当てたもの)が、パネルの見た目を変えない。パネルの CSS が、見本のページを変えない。
- 見本のページのスクリプトから、iframe の中の内容を読めない。
- 送り元の違う `postMessage` を無視する。
- 開いたページのクエリ文字列とハッシュが、送られていない。
- `data-launcher="none"` と `data-helpdesk-open`、`Helpdesk.open()`、`Helpdesk.prefill()` が働く。
- 幅 375px で全画面になり、キーボードだけで最後まで操作できる。axe の違反が無い。
- `widget.js` の大きさが、決めた上限を超えない。

- 「自動で確かめること」のテストがあり、通っている。
