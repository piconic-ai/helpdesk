# 運営画面を「毎日使える」水準に上げる

問い合わせに答える流れは、最後まで通せるようになりました。次は、毎日使う道具としての質を上げます。一覧で判断できること、操作の置き方に一貫性があること、余白と文字が整っていること、ユーザーが行き止まりにならないこと、の4つです。

置き場所は `docs/plan/ux-fixes-2.md` です。goal には次の1文を渡します。

```
docs/plan/ux-fixes-2.md を読み、指摘と決まりをすべての画面に反映してください。「完了の条件」をすべて満たしたら完了です。
```

`docs/plan/ux-fixes.md` の決まり、`DESIGN.md`、層の決まり、振る舞いの決まりは変えません。この文書で `DESIGN.md` に足す内容は、同じ commit で `DESIGN.md` に書きます。

## 1. 一覧で判断できるようにする

一覧は、会話を開かずに「どれから手を付けるか」を決める場所です。いまの行は、どのプロダクトの話かが分かりません。

行に出すもの:

- **プロダクト**: 「すべてのプロダクト」を見ているとき、行にプロダクト名を出す。1つのプロダクトに絞っているときは出さない。
- **種別**: 最後のメッセージの種別(受信・返信・メモ・承認待ち)。文字の前置きではなく、小さなアイコンと読み上げ用の名前で示す。
- **待たせている時間**: 未対応の行では、相手の最後のメッセージからの経過時間を出す。24時間を超えたら文字を濃くする。色は使わない。
- **やりとりの数**: メッセージが3通以上あるとき、数を出す。
- **添付**: 添付があるとき、印を出す。
- **担当者**: アイコン1つ。頭文字は1文字にし、丸の中で折り返さない。

一覧の操作:

- 並び順を選べる(待たせている順、新しい順)。既定は待たせている順とし、見出しの横に現在の並びを示す。
- 行にポインターを置くかフォーカスすると、「自分が担当する」「完了にする」を行の右に出す。キーボードでも同じ操作に届く。
- 複数の行を選び、まとめて担当者・ラベル・完了・迷惑メールを適用できる。
- 件数が多いときのページ送りを持つ。URL に状態を持ち、戻る操作で同じ位置に戻る。
- 空の一覧は、その一覧が何を意味するかを1文で示す。

## 2. 運営者のアカウント

運営者を、メールアドレスではなく人として表示します。

- 運営者は、自分の表示名とアイコン画像を設定できる。場所は、サイドバー下部の自分の表示から開く「アカウント」。
- アイコンは画像をアップロードする。受け付ける形式と大きさを検証し、正方形に切り抜いて R2 に保存する。配信は、型を固定し、`nosniff` を付ける。画像が無いときは頭文字1文字を表示する。
- 表示名とアイコンは、一覧、会話の見出し、メッセージの差出人、内部メモ、操作の記録、絞り込みの候補に使う。
- 相手に届くメールの差出人名を、プロダクトごとに設定できる(例: 「Slide サポート」)。運営者の個人名を出すかどうかは、プロダクトごとに選ぶ。既定は出さない。
- エージェントと拡張は、人と見分けられる固有のアイコンで表示する。人の顔や名前を持たせない。
- サイドバーの下部に、いまログインしている運営者を表示する。

## 3. 操作の置き方を揃える

操作ごとに、その場で済ませるか、重ねて出すか、画面を移るかを、次の基準で決めます。すべての操作をこの表に当てはめ、当てはまらない置き方を直します。

| 置き方 | 使う場面 | 例 |
|---|---|---|
| その場で切り替える | 1回の操作で済み、取り消せる | 完了にする、自分が担当する、ラベルを外す、確認済みにする |
| ポップオーバー | 候補から1つ選ぶ。文脈を見たまま行う | 担当者を選ぶ、ラベルを選ぶ、記事を添える、定型文を選ぶ、保留の日時を選ぶ |
| 確認のダイアログ | 取り消せない、または外へ出る | データの削除、承認して送信、issue の起票、会話の統合、拡張の無効化 |
| 横のパネル | 会話を見ながら参照する | 相手の過去の会話、紐づく issue、拡張の情報 |
| 画面を移る | まとまった作業で、URL を共有したい | 会話を開く、記事を書く、設定、集計、拡張の設定 |

決まり:

- ダイアログは、開いたら最初の操作にフォーカスを移し、Esc で閉じ、閉じたら元の操作にフォーカスを戻す。背後は操作できない。
- ダイアログの中で、別のダイアログを開かない。
- 取り消せる操作には確認を挟まず、結果の知らせに「元に戻す」を付ける。
- 確認のダイアログは、何が起きるかを具体的に書く(誰に送るか、何件消えるか)。ボタンの文言は「OK」ではなく動詞にする。
- 入力の途中で画面を離れるときは、下書きを保持する。返信欄は、会話ごとに下書きを残す。
- 会話の画面の「会話の詳細」の折りたたみを無くす。よく使う操作は見出しの行とポップオーバーへ、参照する情報は横のパネルへ分ける。
- 見出しの行は、状態・担当者・ラベルまでにする。そのほかの操作は「その他の操作」のメニューにまとめる。幅が狭いときも1行に詰め込まない。

キーボード:

- 一覧: `j` / `k` で移動、`Enter` で開く、`e` で完了、`a` で自分が担当する。
- 会話: `r` で返信欄へ、`n` で内部メモへ、`Cmd/Ctrl + Enter` で送信、`u` で一覧へ戻る。
- `?` で一覧を表示する。入力欄にフォーカスがあるときは、文字キーの操作を無効にする。

## 4. 余白と文字を整える

画面ごとに場当たりで決まっている値を、`DESIGN.md` の尺度に揃えます。次の手順で、すべての画面を点検します。

1. 画面の一覧を、幅 1440px・1024px・375px で撮る。
2. 次の項目を、画面ごとに確かめて直す。
3. 直したあとを撮り、前後を並べる。

点検する項目:

- **そろえ**: 同じ列にある要素の左端が揃っている。見出し、検索欄、一覧、カードの左右の端が、ページの同じ線に乗っている。
- **間隔**: 関係の近いものほど近く、遠いものほど遠い。区切りの間隔は `lg`、関連する操作の間は `sm`、ラベルと入力欄の間は `xs`。同じ役割の間隔が、画面によって違わない。
- **文字**: 画面の見出しは `title-lg`、区切りの見出しは `title-sm`、操作まわりは `body`、読む文章は `reading`、補足は `caption`。この5つ以外の大きさが無い。1画面で使う大きさは4つまで。
- **行の高さ**: 一覧の行、ボタン、入力欄、ナビの項目が、`DESIGN.md` の高さになっている。
- **幅**: 読む文章は 680px を超えない。フォームの入力欄は、内容に合う幅にする。短い値の欄を、画面いっぱいに広げない。
- **重み**: 1画面に主ボタンは1つ。濃い要素が競合していない。
- **日本語**: 助詞や句読点の前で不自然に折り返さない。数字と単位が行をまたがない。省略は末尾の「…」で行い、全文をツールチップで読める。
- **数値**: 時間は読める単位にする(「5,760分」ではなく「4日」)。件数と割合は桁をそろえ、右に寄せる。
- **状態**: 読み込み中、空、エラー、無効の見た目が、どの画面でも同じ作りになっている。

`DESIGN.md` に足すもの: ポップオーバー、ダイアログ、横のパネル、メニュー、アカウントのアイコン(画像と頭文字)、一覧の行の追加要素、まとめて操作するバー、キーボード操作の一覧。

## 5. ユーザーを行き止まりにしない

ユーザー側は、自分で解決できなかったときの出口が欠けています。解決までの時間に直接効く箇所です。

- **ヘルプチャット**: 記事を示したあとに、「解決しなかったので問い合わせる」を置く。押すと、入力した質問を引き継いで問い合わせになり、番号を返す。入力した質問を、結果の画面にも表示する。
- **ヘルプ記事**: 「役に立ちましたか」で「いいえ」を選んだら、問い合わせへの導線を示す。記事の下に、常に問い合わせへのリンクを置く。
- **ヘルプページの一覧**: 検索できる。記事が無いときは、問い合わせへ案内する。
- **問い合わせと フィードバックの完了画面**: 番号、返信が届く宛先、返信の目安(設定されている場合)を示す。フィードバックは、返信を送らないことを明記する。
- **公開の画面のエラー**: 送れなかったときに、入力した内容を保持し、もう一度送れる。

## 6. そのほかの指摘

| 画面 | 起きていること | あるべき姿 |
|---|---|---|
| 集計 | 数値が並ぶだけで、定義が分からない | 数値ごとに1行の定義を付ける。前の同じ長さの期間との差を示す。件数が少ないときは「目安」と明記する |
| ヘルプチャットの設定 | 埋め込み先の登録が、設定のキー名(`publicIntakes.origins`)で説明されている | 画面で埋め込み先を登録できる。キー名を画面に出さない |
| 定型返信 | 選択肢が内部の名前(`acknowledge`)のまま | 定型文に表示名を持たせる。定型文を画面で作成・編集できる |
| 拡張の管理 | 16個が縦に並び、必要なシークレットが未設定かどうか分からない | 設定が足りない拡張に「設定が必要」と示す。用途(受け付ける、答える、直す、整える)でまとめる |
| 振り分けルール | 保存済みのルールの一覧が見当たらない | 一覧、編集、削除、並べ替えができる。どの会話に適用されたかを、会話の記録で分かる |
| 操作の記録 | 会話の画面で、誰がいつ何をしたかを追いにくい | メッセージの間に、状態・担当者・ラベルの変更を、控えめな1行として時系列で挟む |

## 確かめていない場面

次の場面は、画面を操作して確かめていません。通しのテストと、ブラウザでの操作で確かめてください。

- 承認待ちの下書き: 一覧での印、編集してから承認、破棄
- フィードバックの投稿、確認、問い合わせへの変換
- 問い合わせフォーム、issue の起票と紐づけ、スヌーズ、統合
- メールの受信から会話になるまで
- API トークンの発行と、CLI・MCP からの操作
- 幅 375px での全画面と、キーボードだけでの操作

## 自動で確かめること

- 通しの場面(`ux-fixes.md` の J1〜J11)に、次を足す。
  - J12: チャットで記事が示され、「解決しなかった」から問い合わせになり、番号が返る。運営の一覧に、質問の文と一緒に出る
  - J13: 一覧で複数の行を選び、まとめて担当者とラベルを付け、完了にする。「元に戻す」で戻る
  - J14: 運営者が表示名とアイコンを設定し、一覧・会話・記録に反映される
  - J15: キーボードだけで、一覧から会話を開き、返信し、次の未対応へ進む
- ダイアログ: フォーカスの移動、Esc、背後が操作できないことを、すべてのダイアログで検査する。
- 文字の大きさと余白: 描画後の値を調べ、`DESIGN.md` の尺度に無い値が無いことを、画面の一覧のすべてで検査する。
- 折り返し: 一覧の行とバッジが、3つの幅で想定の行数に収まることを検査する。長い件名、長い名前、ラベルが多い行を例示データに含める。
- アイコンのアップロード: 画像でないファイル、大きすぎるファイル、偽った拡張子を拒むこと。
- 見た目の回帰: 直した画面のスクリーンショットを更新する。
