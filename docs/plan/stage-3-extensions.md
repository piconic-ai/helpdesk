# 段階3: 残りの拡張

固まった口の上に、残りの拡張をすべて作ります。拡張は互いに独立しているため、行き詰まったものは「未完」と記録して次へ進み、最後に戻ります。

## 作る順番

既定で有効なものから作ります: `spam` → `notify` → `auto-ack` → `metrics` → `feedback` → `articles` → `chat` → `survey` → `export` → `snooze` → `merge` → `rules` → `presence`。

拡張ごとに `docs/features/` に仕様を書き、下の「できること」を受け入れ条件に展開します。口を変える必要が出たら、変える前に、既存の拡張への影響を `docs/decisions.md` に書きます。

## 同梱する拡張

| 拡張 | 口 | できること | 既定 |
|---|---|---|---|
| `spam` | 出口 | 迷惑メールを隔離する。確認して戻せる | 有効 |
| `notify` | 出口 | 新着と、担当になったことを知らせる | 有効 |
| `auto-ack` | 出口 | 届いたことを、問い合わせ番号と一緒に相手へ伝える | 有効 |
| `metrics` | 出口・画面 | A・D・F をプロダクト別・期間別に見る | 有効 |
| `form` | 入口 | プロダクト内のフォームから問い合わせを受け、番号を返す | 無効 |
| `canned` | 操作・画面 | 定型返信。相手の名前とプロダクト名を差し込む | 無効 |
| `issues` | 出口・操作・画面 | 会話から issue を起こす。既存の issue に紐づける。issue が閉じたら、声を寄せた人への返信の下書きを作る | 無効 |
| `feedback` | 入口・画面 | 返信不要の一言を受け取り、届いたことを伝える | 無効 |
| `articles` | 操作・画面 | ヘルプ記事を書いて公開する。プロダクト別のヘルプページ、検索、返信への記事の添付、「記事にする候補」の記録、役に立ったかの一問 | 無効 |
| `chat` | 入口 | 質問に合う記事を示す。合う記事が無ければ、入力した内容のまま問い合わせにして番号を返す | 無効 |
| `survey` | 出口 | 完了のあとに、解決したかを一問だけ尋ねる | 無効 |
| `snooze` | 操作・画面 | あとで対応する。時刻が来たら一覧に戻る | 無効 |
| `merge` | 操作 | 同じ件の会話を1つにまとめる | 無効 |
| `rules` | 出口 | 条件に合う会話に、ラベルと担当者を自動で付ける | 無効 |
| `presence` | 画面 | 同じ会話を開いている人、返信を書いている人を表示する | 無効 |
| `export` | 操作 | 会話と出来事を書き出す | 無効 |

ヘルプチャットは文章を作りません。判断を純粋な関数に置き、モデルの呼び出しは client に閉じ込めます。

```ts
function decideChat(scores: ArticleScore[], threshold: number):
  | { kind: 'show_articles'; articles: ArticleId[] }
  | { kind: 'hand_off' }
```

`issues` は、同じ原因の声が何件あるかを issue ごとに数え、プロダクトに届いた声全体に占める割合を、直す前と後で比べられるようにします。件数が少ないうちは値が大きく振れるため、画面には「目安」と明記します。

## 拡張ごとの要点

- **`spam`**: 隔離したメールは一覧から確認でき、戻せる。隔離された相手には、受付返信を送らない。
- **`notify`**: 通知に本文を載せるかは設定で選べる。既定では件名と番号だけ。
- **`auto-ack`**: 新しい会話の最初の1通にだけ送る。自動送信メール、バウンス、隔離されたメールには送らない。文面に自動送信であることを明記する。承認は `standing` として記録する。
- **`metrics`**: A・D・F をプロダクト別・期間別に出来事から計算する。計算は純粋な関数にし、例示データで確かめる。A の「解決した」は、記事での一問と会話の完了から推定する。
- **`feedback`**: 返信の状態を持たない会話として受け取る。返事をしたいときは「問い合わせに変える」操作を通す。
- **`articles`**: 公開した記事だけがヘルプページに出る。Markdown の表示は無害化する。返信に記事を添えられる。会話から「記事にする候補」を記録できる。
- **`chat`**: 文章を作らない。合う記事を示すか、入力した内容のまま問い合わせにして番号を返すかの、どちらかになる。判断のテストは、点数を固定して行う。
- **`survey`**: 完了のあとに一問だけ尋ねる。答えは出来事として記録し、D の計算に使う。
- **`export`**: 名前とアドレスは既定で伏せる。CLI と MCP からも書き出せる。
- **`snooze`** と **`merge`**: 核の型を広げず、自分のテーブルで実現する。統合した会話の番号で届いたメールは、統合先に入る。
- **`rules`**: 条件の評価は純粋な関数にする。規則が自動で返信を送ることはない。
- **`presence`**: 表示だけを行う。他人が書いている返信の送信は妨げない。

## 完了の条件

- すべての拡張に仕様があり、受け入れ条件が自動テストで確かめられている。未完のものは、理由と一緒に報告に書かれている。
- すべての拡張を有効にした状態と、すべて無効にした状態の両方で、段階1の受け入れ条件が通る。
- `05-verification.md` のコマンドがすべて通る。
- 報告が `docs/reports/stage-3.md` にある。
