# 指針に照らしたレビューと、残りの直し

プロダクト指針の10項目と北極星の数値に照らして、画面を操作して確かめた結果です。運営側の基本の流れは指針を満たしています。足りないのは、指針の後半、「声を改善につなげる」「直す」を画面で回せるところと、誠実さを運営者が確かめられるところです。

置き場所は `docs/plan/review-4.md` です。goal には次の1文を渡します。

```
docs/plan/review-4.md を読み、「直すこと」をすべて反映してください。「完了の条件」をすべて満たしたら完了です。
```

## 直すこと

### A. 指針に届いていないもの

1. **「直す」を回す画面を作る。** サイドバーに「課題」を置く。issue ごとに、題、プロダクト、紐づく声の数、状態(開いている・閉じた)、閉じたあとに知らせた数を一覧する。閉じた issue には、知らせる下書きを作る操作を置く。プロダクトに届いた声全体に占める割合を、直す前後で比べて表示し、「目安」と明記する。
2. **E を集計に足す。** 届いた声のうち、issue に紐づき、直ったあとに知らせが届いた割合。
3. **声を眺める画面を作る。** 問い合わせとフィードバックを合わせて、ラベル別・プロダクト別・期間別の件数を見られる。行を押すと、その条件の一覧に移る。
4. **記事の候補を一覧する。** ヘルプ記事の画面に「候補」を置き、元の会話を見ながら記事を書き始められる。
5. **自動で送る文面を見せる。** 自動受付返信と解決アンケートの設定に、実際に届く文面のプレビュー、自動送信であることの明記、誰がいつ有効にしたかを出す。文面はプロダクトごとに編集できる。
6. **起票先が未設定のときに案内する。** 会話の画面で issue を起票しようとしたとき、リポジトリやトークンが未設定なら、その場で設定への導線を示す。拡張の一覧でも「設定が必要」と表示する。

### B. 見た目と操作

| 画面 | 起きていること | あるべき姿 |
|---|---|---|
| 確認のダイアログ | 開くと、背後のページが下へずれ、上に白い帯が出る | 背後は動かさない。スクロール位置を保つ |
| 確認のダイアログ | 2つのボタンが同じ見た目 | 実行するボタンを主ボタンにし、右に置く |
| 承認待ちの下書き | 「承認して送信」「下書きを破棄」が縦に2段で、どちらも副ボタン | 横に並べ、承認を主ボタン、破棄を控えめにする |
| 会話の画面 | 関連情報(記事・スヌーズ・定型返信・Issue・過去の問い合わせ・操作履歴)がページの下にあり、「その他の操作」のメニューからページ内リンクで飛ぶ | 幅 1200px 以上では右のパネルに常に出す。狭い幅では、見出しの行のボタンから開くパネルにする |
| 会話の画面 | 定型返信、スヌーズ、Issue が、関連情報の中のフォームになっている | 定型文は返信欄から選ぶ。スヌーズは「その他の操作」から日時を選ぶ。Issue は右のパネルに現在の紐づけを出し、起票は確認のダイアログで行う |
| 会話の画面 | 担当者が未設定のとき、空の丸と「担当: 担当なし」が並ぶ | 「担当者を選ぶ」の1つの表示にする |
| 拡張の管理 | 「有効」のバッジが、幅が狭いカードで2行に折れる | 折り返さない。題が長いときは題を省略する |
| 拡張の管理 | 区切りの見出し(受け付ける、答える)とカードの間が詰まっている | 区切りの間隔を `DESIGN.md` の `lg` に揃える |
| 集計 | カードが6枚同じ大きさで並び、説明の文が長い | 北極星の3つを上段に大きく、件数は下段に小さく。定義は1行にし、詳しい説明はツールチップへ |
| 集計 | 「直前の同じ日数と比較しています…」がカードの段の間に挟まっている | 条件の帯の下に置く |
| ヘルプ記事の一覧 | 1行に題と補足が同じ調子で並ぶ | 題を主にし、プロダクト・更新日・評価は列として右に揃える |
| 画面の切り替え | 切り替えの直後、内容が薄い状態がしばらく見える | フェードは 150ms 以内。計測して確かめる |
