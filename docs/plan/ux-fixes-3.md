# 画面を「部品の組み合わせ」に作り直す

受信箱と会話の画面は整ってきましたが、ほかの画面は素の HTML に近いままです。画面ごとに HTML と CSS を書いているため、直した画面だけが良くなり、全体の質が揃いません。この文書は、先に画面の型と部品を作り、すべての画面をその組み合わせに置き換える手順を示します。

置き場所は `docs/plan/ux-fixes-3.md` です。goal には次の1文を渡します。

```
docs/plan/ux-fixes-3.md を読み、部品の見本を先に作ってから、すべての画面を部品の組み合わせに置き換えてください。「完了の条件」をすべて満たしたら完了です。
```

これまでの決まり(`DESIGN.md`、`ux-fixes.md`、`ux-fixes-2.md`、層、振る舞い)は変えません。

## 進め方

1. **部品の見本を作る。** `/dev/ui`(開発時だけ有効)に、下の「画面の型」と「部品」を、状態の違いを含めてすべて並べる。例示データで描画し、3つの幅で崩れないことを確かめる。
2. **部品は BarefootJS の UI コンポーネントを土台にする。** ボタン、入力欄、選択、ポップオーバー、ダイアログ、メニュー、タブ、ツールチップは自作せず、既存のコンポーネントに `DESIGN.md` のトークンを当てる。`pnpm exec bf docs` と `https://ui.barefootjs.dev` で確かめる。足りないものだけを作る。
3. **画面を置き換える。** すべての画面を、型と部品の組み合わせだけで組む。画面のファイルに、その画面だけの CSS を書かない。
4. **検査を足す。** 画面のファイルが、部品以外の要素に直接クラスやスタイルを書いていないことを検査する。

見本を作り終えた時点で、`docs/reports/ux-3/gallery/` に画像を出し、そのまま置き換えへ進みます。

## 画面の型

どの画面も、次の4つのどれかです。型ごとに、見出し・操作・本文の位置を固定します。

| 型 | 構成 | 使う画面 |
|---|---|---|
| 一覧 | 見出しと件数、主な操作(右上)、検索と絞り込みの帯、行の一覧、ページ送り | 受信箱、フィードバック、ヘルプ記事、振り分けルール、定型返信、API トークン、運営者 |
| 詳細 | 戻るリンク、見出し、属性の行、本文の列(最大 760px)、右のパネル | 会話、記事のプレビュー |
| 編集 | 戻るリンク、見出し、1列のフォーム(最大 560px)、下部に保存と取り消し | 記事を書く、プロダクトと窓口、拡張の設定、アカウント |
| 概要 | 見出し、条件の帯(1行)、数値のカードの格子、補足 | 集計、設定の入口、拡張の管理 |

## 部品

見本に、次の部品を状態ごとに並べます。

- **ページの見出し**: 題、補足(件数など)、右に主な操作を1つ。
- **条件の帯**: 検索、絞り込み、並び順を1行に収める。絞り込みは入力のたびに反映し、「検索」ボタンを置かない。適用中の条件は、外せるチップで示す。
- **一覧の行**: 会話用(2行)と、汎用(1行: 題、補足、状態、右端に操作)。
- **設定の行**: 左に題と1行の説明、右に現在の値と「>」。行全体が押せる。青い下線のリンクを並べない。
- **数値のカード**: 題、大きな数値、前の期間との差、1行の定義。
- **フォームの区切り**: 題、説明、入力欄の組。入力欄は内容に合う幅。
- **属性の行**: 状態・担当者・ラベルを、枠のない控えめな表示で並べる。押すとポップオーバーが開く。
- **操作の帯**: 主な操作1つ、副の操作、そのほかはメニュー。
- **メッセージ**: 受信、返信、内部メモ、記録の1行。
- **返信欄**、**ポップオーバーの候補一覧**(アイコン付き、現在の選択に印)、**確認のダイアログ**、**知らせ**、**空の状態**、**読み込み中**、**拡張のカード**。

## 画面ごとの指摘

画面を見て確かめたものです。

### 受信箱

- 未対応の一覧で、すべての行に「未対応」のバッジが出る。見ている一覧と同じ状態のバッジは出さない。状態が混ざる一覧(すべて、自分の担当、検索結果)でだけ出す。
- チェックボックスが行の左上に浮き、2行のどちらとも揃っていない。行の縦の中央に置き、ふだんは薄く、行にポインターを置いたときと選択中にはっきり見せる。
- 差出人、プロダクト、件名が1行に同じ調子で並び、どれが主か分からない。差出人を主、件名を次、プロダクトは控えめなチップにする。既読の行は、差出人と件名の太字を外す。
- 右端に、バッジ・ラベル・状態・担当者が詰まっている。状態のバッジを外したうえで、右端は時間と担当者だけにし、ラベルと印は2行目に置く。
- 「検索」ボタンを無くし、条件の帯に置き換える。

### 会話

- 見出しの下が、枠付きのボタンの列になっている(担当、ラベル、完了、その他)。属性(状態・担当者・ラベル)は枠のない「属性の行」に、操作(完了、その他)は見出しの右の「操作の帯」に分ける。
- 「次の未対応へ」が右端に下線付きのリンクで浮いている。操作の帯に、前後へ進む矢印として置く。
- 担当者のポップオーバーに、アイコンと現在の選択の印が無い。
- 返信欄が大きな枠の中に素の入力欄として置かれ、どこまでが入力の範囲か分かりにくい。切り替え、入力、下部の操作を1つの部品としてまとめる。

### サイドバー

- 「キーボード操作 ?」だけが太字で、並びから浮いている。下部を「拡張の管理・設定」と「アカウント」の2段に整理し、キーボード操作はアカウントのメニューか `?` キーに寄せる。
- 「API トークン」は設定の中にある。サイドバーから外す。
- 拡張の2項目が同じアイコンになっている。項目ごとに意味の合うアイコンを当てる。

### ヘルプ記事の一覧

- 箇条書きの点と青い下線のリンクが1つあるだけになっている。「一覧」の型にし、行に題、プロダクト、公開の状態、更新日、役に立った割合を出す。

### 設定

- 箇条書きの点がカードの外にはみ出し、青い下線のリンクが並ぶ。「設定の行」に置き換え、項目ごとに1行の説明と現在の値(例: 窓口 2件、運営者 2人、保存期間 無期限)を出す。
- 「データ管理」は離して置き、消える操作であることを説明する。

### 集計

- 条件が縦に5段積まれ、画面の半分を占める。「条件の帯」1行に収め、変えたら「集計する」を押さずに反映する。
- 数値が右端に小さく離れて出る。「数値のカード」を3つ並べ、北極星の数値を先頭に大きく出す。
- 「比較データなし」は、何が足りないかを1行で説明する。

### 拡張の管理

- カードの中が、説明、下線のリンク、権限の文、ボタンの順に積まれ、文字が多い。「拡張のカード」として、題と1行の説明、右上に有効・無効の切り替え、下部に「設定」を置く。権限は、有効にするときの確認と設定の画面で示す。
- 「使用する権限追加の権限はありません」のように、題と値がつながって読める。題と値を分ける。

## 仕上げの基準

置き換えのあと、すべての画面で次を確かめます。

- 青い下線のリンクは、文章の中と公開の画面にだけある。運営画面の移動は、行・ボタン・ナビで行う。
- 箇条書きの点が、運営画面のどこにも無い。
- 1画面の中で、枠付きのボタンが4つ以上横に並んでいない。
- 見出しの左端と、本文の左端が同じ線に乗っている。カードの内側の余白が、どの画面でも同じ。
- どの画面も、ポインターを置いたとき、フォーカスしたとき、押したとき、無効なときの見た目を持つ。
- 画面の切り替えと、ポップオーバーの開閉に、150ms のフェードがある。位置は動かさない。

## 完了の条件

- `/dev/ui` に、型と部品が状態ごとに並んでいる。
- すべての画面が、型と部品の組み合わせだけで組まれている。これを検査するテストがある。
- 「画面ごとの指摘」がすべて直っている。
- 「仕上げの基準」を検査するテストがあり、通っている。
- これまでの通しのテスト(J1〜J15)と、`docs/plan/05-verification.md` のコマンドがすべて通る。
- レビュー用の成果物が揃っている。
