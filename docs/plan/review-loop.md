# 自分で見て、直して、また見る

人のレビューに出す前に、自分で画面を操作し、基準に照らして指摘を出し、直し、もう一度見ます。指摘が出なくなるまで繰り返します。人に見せるのは、この繰り返しを終えたあとの状態です。

置き場所は `docs/plan/review-loop.md` です。goal には次の1文を渡します。

```
docs/plan/review-loop.md の手順で、見る・直すを繰り返してください。「終える条件」を満たしたら完了です。
```

`docs/plan/` に未対応の指示(`ux-fixes-*.md`)があれば、先にそれを済ませてから始めます。`ux-fixes-6.md` の手がかり(アイコン、点、印)も、基準の「揃え」「言葉」と同じように確かめます。

## 1周の手順

1. **撮る。** 例示データを入れ直し、すべての画面を、すべての状態で、幅 375px・1024px・1440px で撮る。ポップオーバー、ダイアログ、パネル、メニューは、開いた状態も撮る。
2. **歩く。** 5つのワークフローを、運営者とユーザーの立場で、ブラウザを操作して端から端まで通す。手順ごとに、操作の回数、迷った箇所、待たされた箇所を記録する。
3. **見る。** 撮った画像を1枚ずつ開き、下の「基準」の項目ごとに確かめる。コードではなく、画像を見て判断する。1画面につき、少なくとも3つの指摘を探す。見つからなければ、その旨を記録する。
4. **書く。** 指摘を `docs/reports/loop/round-N.md` に、画面・起きていること・あるべき姿・重さ(高・中・低)で書く。
5. **まとめる。** 同じ原因の指摘をまとめ、部品や決まりの側で直せるものを先に選ぶ。1か所だけの直しは後にする。
6. **直す。** 重さが高と中のものを、すべて直す。低は、同じ部品を触るついでに直す。
7. **守る。** 直した指摘が再び起きないよう、検査できるものはテストにする。
8. **確かめる。** `docs/plan/05-verification.md` のコマンドと、通しのテストをすべて通す。

1周を終えたら、確認を待たずに次の周へ進みます。

## 基準

### 画面を見て確かめること

- **目的**: この画面を、誰が、何のために開くかを1文で言える。画面のいちばん目立つものが、その目的に合っている。
- **順位**: 目を細めて見たとき、最初に目に入るものが1つに決まる。主ボタンは1つ。同じ強さの要素が4つ以上並んでいない。
- **まとまり**: 関係のあるものが近く、関係のないものが離れている。まとまりの数は、1画面に5つまで。
- **揃え**: 左端の線が、画面の中で3本以内に収まる。数は右に寄り、桁が揃っている。同じ行のカードの高さが揃っている。
- **間隔**: 枠や背景を持つ要素どうしが接していない。同じ役割の間隔が、画面によって違わない。
- **文字**: 大きさは、1画面に4種類まで。折り返してはいけない言葉(番号、件数、日付、状態、ボタン)が折れていない。省略された言葉が、意味を失っていない。
- **言葉**: 内部の名前、ID、英語の仮の名前、機械の単位が出ていない。同じものを、画面によって別の名前で呼んでいない。ボタンは動詞で、押すと何が起きるかが分かる。
- **状態**: 空、読み込み中、エラー、無効、選択中、フォーカス中の見た目がある。空の状態は、次に何をすればよいかを示す。
- **幅**: 375px で横にはみ出さない。1440px で、内容が間延びしない。

### 歩いて確かめること

- **つながり**: 1つの作業を終えたとき、次の作業への入口がその場にある。行き止まりが無い。
- **回数**: いちばん多い操作(開く、返信する、完了にする、次へ進む)に、余計な確認や画面の移動が挟まっていない。
- **場所**: その場で済む操作のために、別の画面へ移らない。移ったあと、元の場所へ戻れる。
- **知らせ**: 操作のあと、何が起きたかが分かる。取り消せる操作には「取り消す」がある。
- **入力**: ID、メールアドレス、機械の単位を打たせていない。必須でない欄を必須にしていない。送れなかったとき、理由が出て、入力が残る。
- **速さ**: 画面の切り替えと、操作への反応に、待たされる感じが無い。
- **指針**: 相手に届くものは、送る前に確かめられる。自動で送るものは、人のふりをしない。エージェントと拡張の送信は、人が承認するまで出ない。内部メモは、相手に送られない。

### 比べて確かめること

- すべての画面を縮小して1枚に並べ、見出しの位置、余白、ボタンの形、カードの作りが、画面によって違っていないかを見る。
- 同じ種類の画面(一覧どうし、設定どうし)を横に並べ、違いに理由があるかを確かめる。

## 終える条件

次のすべてを満たしたら終えます。

- 続けて2周、重さが高と中の指摘が出なかった。
- 5つのワークフローのすべての手順を、ブラウザで通した記録がある。
- 少なくとも3周を終えている。

10周を超えても終わらないときは、残っている指摘と、直せない理由を報告して止まります。

## 人に渡すもの

- `docs/reports/loop/summary.md`: 周ごとの指摘の数(重さ別)、直したことの要点、部品や決まりの側で直したこと、残した指摘と理由。
- `docs/reports/loop/index.html`: 全画面の、最初の周と最後の周の画像を、3つの幅で並べたもの。
- `docs/reports/loop/contact-sheet.png`: 全画面を縮小して1枚に並べたもの。
- `docs/reports/workflows.md`: ワークフローの手順ごとに、画面でできるか、通しのテストがあるか。
- 自分では判断できず、人に決めてほしいこと。3件までに絞る。

## やってはいけないこと

- 指摘を、検査や基準を緩めて消すこと。
- 画像を見ずに、コードやテストの結果だけで「問題なし」とすること。
- 1周で見る画面を減らすこと。
- 振る舞いの決まり(承認、内部メモ、差出人の決め方)を変えること。
