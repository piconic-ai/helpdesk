# helpdesk ハンズオン

例示データの入ったローカルの環境で、問い合わせに答えるところから、声を改善につなげるところまでを、30分ほどで一通り体験します。運営者「佐藤 優」としてログインしている前提です。

動作確認にはローカルの例示データを使います。メールの送信と GitHub の操作は模擬サービスで確認できます。

## 準備

1. 開発サーバーを起動し、例示データを入れる。[例示データでの起動手順](dev/development.md)に従う。
2. ターミナルに表示されたローカル URL をブラウザで開く。
3. 左下に自分の名前が出ていること、「未対応」に数件の問い合わせが並んでいることを確かめる。

## 1. 受信箱を読む(3分)

W1 · 通しのテスト H01、J13。

受信箱は、どれから手を付けるかを決める場所です。

1. 左上の「すべてのプロダクト」を押し、プロダクトを切り替えてみる。件数が変わる。「すべてのプロダクト」に戻す。
2. 行を読む。上の段に、差出人、件名、プロダクト、待たせている時間。下の段に、問い合わせ番号、最後のメッセージ、印(添付、承認待ち、送信失敗)、ラベル、担当者。
3. 並び順が「待たせている順」になっていることを確かめる。いちばん上が、いちばん長く待たせている相手です。
4. 検索欄に「領収書」と入れて、絞り込まれることを確かめる。消して戻す。
5. 「絞り込み」を開き、担当者やラベルを候補から選んでみる。

確かめること: 会話を開かなくても、「どのプロダクトの、誰が、どれだけ待っているか」が分かる。

## 2. 問い合わせに答える(7分)

W1 · 通しのテスト H02、J1・J2。

1. 担当者のいない問い合わせ（例: #6）を開く。
2. 見出しの下の「担当者を選ぶ」を押し、自分を選ぶ。上に結果の知らせが出る。
3. 「ラベルを選ぶ」を押し、ラベルを1つ付ける。
4. 返信欄に返事を書く。
5. 「記事を添える」を押し、題名で記事を探して選ぶ。本文に記事へのリンクが入る。
6. 「プレビュー」を押す。差出人が窓口のアドレス、件名に `[#6]` が付いていることを確かめる。
7. 「送信して完了」を押す。送信を取り消せる間は「取り消す」が表示される。そのまま待つと送信され、会話が「完了」になる。
8. 見出しの右の矢印で、次の未対応へ進む。

確かめること: メールアドレスや ID を一度も打たずに終えられる。相手に届く形を、送る前に確かめられる。

## 3. 内部メモを残す(2分)

W1 · 通しのテスト H03、J14。

1. 別の問い合わせを開く。
2. 返信欄の上の「内部メモ」に切り替える。欄の色が変わり、「相手には送られません」と出る。
3. メモを書いて残す。メッセージの並びに、色の違うメモとして入る。

確かめること: 返信とメモを取り違えない。

## 4. 送信の失敗に気づいて直す(2分)

W1 · 通しのテスト H04、J3。

1. 受信箱で「送信失敗」の印が付いた問い合わせ(例: #4)を開く。
2. 失敗した返信に、理由が出ていることを読む。
3. 宛先と失敗理由を読み、「再送」を押す。返信の表示が「送信済み」に変わることを確かめる。

確かめること: 返事が届かなかったことを、一覧の時点で見落とさない。

## 5. AI の下書きを承認する(4分)

W1 · 通しのテスト H05、J4。

エージェントは返信の下書きまでを行い、送るかどうかは人が決めます。

1. サイドバーの「承認待ち」を開く。
2. 下書きのある問い合わせ(例: #5)を開く。返信に「エージェント(佐藤 優 の代理)」「承認待ち」と出ている。
3. 下書きの本文を、その場で書き直す。
4. 「承認して送信」を押す。宛先と本文を確認するダイアログが出る。
5. 内容を読み、送信する。または「キャンセル」で戻り、「下書きを破棄」を試す。

確かめること: 人が承認するまで、相手には何も届かない。誰の代理で作られた下書きかが分かる。

## 6. ユーザーの立場で、自分で解決する(5分)

W3 · 通しのテスト H06、J6・J12。

別のタブで、公開の画面を開きます。URL は「拡張の管理」から各拡張の「設定」を開くと出ています。

1. ヘルプチャット(`/help/chat/slide`)を開く。
2. 「領収書を発行したい」と書いて「質問する」を押す。関連する記事が示される。作られた文章は返ってこない。
3. 記事を開いて読む。下の「役に立ちましたか」に答える。
4. チャットに戻り、「解決しなかったので問い合わせる」を押す。連絡先を入れて送る。問い合わせ番号が返る。
5. 運営画面の「未対応」に、その問い合わせが質問の文と一緒に出ていることを確かめる。

確かめること: 待たずに解決できる道があり、解決しなかったときも行き止まりにならない。自動の応答が人のふりをしない。

## 7. 返信不要の声を受け止める(3分)

W2 · 通しのテスト H07、J7。

1. 連絡先を空のまま、フィードバックの公開フォーム(`/help/feedback/slide`)を開き、一言を送る。返信は送られない旨が出る。
2. 運営画面のサイドバーの「フィードバック」を開く。届いた声が並ぶ。
3. 一覧の「確認済みにする」を押す。「元に戻す」で未確認に戻せる。「未確認を先に」に切り替えて未確認の声を探す。
4. 記名の声を開き、返信が必要なら見出し横の「問い合わせに変更」を選ぶ。匿名の声には返信先がない。

確かめること: 返事を求めていない声を、問い合わせと分けて受け取れる。

## 8. 答えるだけで終わらせず、直す(4分)

W4 · 通しのテスト H08、J8。

1. 「拡張の管理」→「GitHub Issue」の「設定」で、プロダクトの起票先のリポジトリを登録する。
2. 問い合わせを開き、右側の関連情報を開く。幅1200px未満では、見出しの「関連情報」を押す。
3. 「Issue を起票する」を押し、公開してよい題と要約を書く。相手の名前、アドレス、本文は載せない。
4. 「起票内容を確認」で、投稿される内容を読んでから起票する。
5. 同じ原因の別の問い合わせでは、関連情報の「既存の Issue を選ぶ」を開き、題を検索して紐づける。
6. サイドバーの「課題」で開閉状態と声の数を確認する。「知らせる待ち」から下書きを作り、会話で確認・承認する。課題の題を開くと、知らせた声と修正前後の件数を確認できる。
7. 同じ質問が繰り返されそうなら、会話で「記事の候補に追加」を選ぶ。「ヘルプ記事」→「候補」から、元の会話を参照して記事を書き始める。

確かめること: 返信と同じ場所から、改善の入口に進める。公開される内容を、人が確かめてから出せる。

実在のリポジトリへの起票は、試す前に、試験用のリポジトリを登録してください。

## 9. 数値を見る(2分)

W4 · 通しのテスト H09、J10。

1. サイドバーの「対応状況の集計」を開く。
2. 「解決までの平均時間」「一度で解決した割合」「平均作業時間」を読む。
3. プロダクトと期間を変える。前の期間との差が出る。「声が改善に届いた割合」は、修正後の知らせまで届いた声の割合を示す。
4. サイドバーの「声の集計」を開く。ラベル・プロダクト・期間の行を選び、同じ条件の問い合わせとフィードバックが並ぶことを確認する。

確かめること: 追加の入力をしなくても、日々の操作から数値が出る。件数が少ないうちは「目安」と明記される。

## 10. 場を整える(3分)

W5 · 通しのテスト H10、J9・J11。

1. 左下の自分の名前から「アカウント」を開き、表示名とアイコン画像を設定する。受信箱と会話に反映される。
2. 「設定」→「プロダクトと窓口」で、窓口のアドレスを確かめる。返信の差出人は、ここから決まる。
3. 「設定」→「保存期間」と「連絡先のデータ削除」を開き、内容を読む。実行はしない。
4. 「設定」→「API トークンの管理」で、権限が「閲覧」「閲覧・下書き」「閲覧・下書き・会話の管理」に分かれていることを確かめる。

確かめること: 相手のデータを、期間で消すことも、相手単位で消すこともできる。AI に渡す権限を、下書きまでに絞れる。

## 振り返り

次の3つに「はい」と答えられれば、指針どおりに動いています。

- 相手は、普通のメールとして返事を受け取れたか。
- 送るかどうかを、最後は人が決めたか。
- 答えたあとに、記事にするか、直すかへ進めたか。

引っかかった箇所は、番号と手順をメモして、次の直しの材料にします。
