# helpdesk ハンズオン

例示データの入ったローカルの環境で、問い合わせに答えるところから、声を改善につなげるところまでを、30分ほどで一通り体験します。運営者「佐藤 優」としてログインしている前提です。

動作確認にはローカルの例示データを使います。メールの送信と GitHub の操作は模擬サービスで確認できます。

## 準備

1. 開発サーバーを起動し、例示データを入れる。[例示データでの起動手順](dev/development.md)に従う。
2. ターミナルに表示されたローカル URL をブラウザで開く。
3. 左下に自分の名前が出ていること、「未対応」に数件の問い合わせが並んでいることを確かめる。

## 1. 受信箱を読む(3分)

W1 · 通しのテスト H01、J13。

受信箱は、どれから手を付けるかを決める場所です。

1. 左上の「すべてのプロジェクト」を押し、プロジェクトを切り替えてみる。件数が変わる。「すべてのプロジェクト」に戻す。
2. 行を読む。上の段に、プロジェクト、差出人、件名、待たせている時間。下の段に、問い合わせ番号、最後のメッセージ、印(添付、承認待ち、送信失敗)、ラベル、担当者。
3. 並び順が「待たせている順」になっていることを確かめる。いちばん上が、いちばん長く待たせている相手です。
4. 検索欄に「領収書」と入れて、絞り込まれることを確かめる。消して戻す。
5. 「絞り込み」を開き、担当者やラベルを候補から選んでみる。
6. 先頭のチェックボックスを選び、Shift を押しながら別の行を選ぶ。帯に範囲内の件数が出る。「すべて選択」で全行を選び、「選択を解除」または Esc で検索に戻る。

確かめること: 会話を開かなくても、「どのプロジェクトの、誰が、どれだけ待っているか」が分かる。

## 2. 問い合わせに答える(7分)

W1 · 通しのテスト H02、J1・J2。

1. 担当者のいない問い合わせ（例: SLD-5）を開く。
2. 見出しの下の「担当者を選ぶ」を押し、自分を選ぶ。画面の下に「担当者を変更しました。」と出る。
3. 「ラベルを選ぶ」を押し、ラベルを1つ付ける。メニューの印を確認し、Esc で閉じる。
4. SLD-5 では返信欄の上の「返信の候補」で「確認中のお知らせ」を押す。相手の名前を差し込んだ文がカーソルの位置に入る。続けて返事を書き、送る文面に直す。ほかの定型文は「定型文を選ぶ」から探せる。
5. 「記事を添える」を押し、題名で記事を探して選ぶ。本文に記事へのリンクが入る。
6. 「プレビュー」を押す。差出人が窓口のアドレス、件名に `[SLD-5]` が付いていることを確かめる。
7. 「送信して完了」を押す。会話に「送信予定」と残り時間が出る。「今すぐ送る」を押すか、既定の10秒が過ぎると配送が始まり、配送が受理されると会話が「完了」になる。通知を「閉じる」で閉じても、会話内の「取り消す」で本文を返信欄に戻せる。
8. 件名の上にある操作帯の右の矢印で、次の未対応へ進む。

確かめること: メールアドレスや ID を一度も打たずに終えられる。相手に届く形を、送る前に確かめられる。

## 3. 内部メモを残す(2分)

W1 · 通しのテスト H03、J14。

1. 別の問い合わせを開く。
2. 返信欄の上の「内部メモ」に切り替える。欄の色が変わり、「相手には送られません」と出る。
3. メモを書いて残す。メッセージの並びに、色の違うメモとして入る。

確かめること: 返信とメモを取り違えない。

## 4. 送信の失敗に気づいて直す(2分)

W1 · 通しのテスト H04、J3。

1. 受信箱で「送信失敗」の印が付いた問い合わせ(例: SLD-3)を開く。
2. 失敗した返信に、理由が出ていることを読む。
3. 宛先と失敗理由を読み、「再送」を押す。返信の表示が「送信済み」に変わることを確かめる。

確かめること: 返事が届かなかったことを、一覧の時点で見落とさない。

## 5. AI の下書きを承認する(4分)

W1 · 通しのテスト H05、J4。

エージェントは返信の下書きまでを行い、送るかどうかは人が決めます。

1. サイドバーの「承認待ち」を開く。
2. 下書きのある問い合わせ(例: SLD-4)を開く。返信に「エージェント(佐藤 優 の代理)」「承認待ち」と出ている。
3. 下書きの本文を、その場で書き直す。
4. 「承認して送信」を押す。宛先と本文を確認するダイアログが出る。
5. 内容を読み、送信する。または「キャンセル」で戻り、「下書きを破棄」を試す。

確かめること: 人が承認するまで、相手には何も届かない。誰の代理で作られた下書きかが分かる。

## 6. ユーザーの立場で、自分で解決する(5分)

W3 · 通しのテスト H06、J6・J12。

別のタブで、[Slide のヘルプチャット](http://127.0.0.1:8788/help/chat/slide)を開きます。公開 URL は Slide の設定の「拡張の設定」から各受付を開いても確認できます。

1. ヘルプチャット(`/help/chat/slide`)を開く。
2. 「領収書を発行したい」と書いて「質問する」を押す。関連する記事が示される。作られた文章は返ってこない。
3. 記事を開いて読む。下の「役に立ちましたか」に答える。
4. チャットに戻り、「解決しなかったので問い合わせる」を押す。連絡先を入れて送る。問い合わせ番号が返る。
5. 運営画面の「未対応」に、その問い合わせが質問の文と一緒に出ていることを確かめる。

確かめること: 待たずに解決できる道があり、解決しなかったときも行き止まりにならない。自動の応答が人のふりをしない。

## 7. 返信不要の声を受け止める(3分)

W2 · 通しのテスト H07、J7。

1. 連絡先を空のまま、フィードバックの公開フォーム(`/help/feedback/slide`)を開き、一言を送る。返信は送られない旨が出る。
2. 運営画面のサイドバーの「フィードバック」を開く。届いた声が並ぶ。
3. 一覧の「確認済みにする」を押す。「元に戻す」で未確認に戻せる。「未確認を先に」に切り替えて未確認の声を探す。
4. 記名の声を開き、返信が必要なら見出し横の「問い合わせに変更」を選ぶ。匿名の声には返信先がない。

確かめること: 返事を求めていない声を、問い合わせと分けて受け取れる。

## 8. 答えるだけで終わらせず、直す(4分)

W4 · 通しのテスト H08、J8。

1. [Slide の GitHub Issue 設定](http://127.0.0.1:8788/extensions/issues?product=slide)を開き、模擬の起票先を確認する。デモでは登録済みなので、そのまま会話に進める。
2. 問い合わせを開き、右側の関連情報を開く。幅1200px未満では、見出しの「関連情報」を押す。
3. 「課題を起票する」を押し、公開してよい題と要約を書く。相手の名前、アドレス、本文は載せない。
4. 「起票内容を確認」で、投稿される内容を読んでから起票する。
5. 同じ原因の別の問い合わせでは、関連情報の「既存の課題を選ぶ」を開き、題を検索して紐づける。
6. サイドバーの「課題」で開閉状態と声の数を確認する。「知らせる待ち」から下書きを作り、会話で確認・承認する。課題の題を開くと、知らせた声と修正前後の件数を確認できる。
7. 同じ質問が繰り返されそうなら、会話の関連情報で「記事候補を書く」を開き、内容を入力して「記事の候補に追加」を押す。「ヘルプ記事」→「候補」から、元の会話を参照して記事を書き始める。

確かめること: 返信と同じ場所から、改善の入口に進める。公開される内容を、人が確かめてから出せる。

デモの起票先は、Slide と Desk ともに模擬 GitHub です。課題を閉じ、知らせを届け、改善率に反映されるまでの操作は第13章で試せます。

## 9. 数値を見る(2分)

W4 · 通しのテスト H09、J10。

1. サイドバーの「対応状況の集計」を開く。
2. 「解決までの平均時間」「一度で解決した割合」「平均作業時間」を読む。
3. プロジェクトと期間を変える。前の期間との差が出る。「声が改善に届いた割合」は、修正後の知らせまで届いた声の割合を示す。
4. サイドバーの「声の集計」を開く。ラベル・プロジェクト・期間の行を選び、同じ条件の問い合わせとフィードバックが並ぶことを確認する。

確かめること: 追加の入力をしなくても、日々の操作から数値が出る。件数が少ないうちは「目安」と明記される。

## 10. 場を整える(3分)

W5 · 通しのテスト H10、J9・J11。

1. 左下の自分の名前から「アカウント」を開き、表示名とアイコン画像を設定する。受信箱と会話に反映される。
2. 「設定」→「プロジェクトの設定」で Slide を選び、「設定を開く」を押す。「窓口と差出人」で返信に使うアドレスを確かめる。
3. Slide の設定に戻り、「保存期間」を開く。「無期限」と「日数を指定」の違いを確認する。「連絡先のデータ削除」では対象を選んで内容を読み、実行せずに戻る。
4. Slide の設定の「ラベル」で「ラベルを追加」を開く。色の点で色を、名前でラベル名を変えられる。「操作」からは会話の件数を確認して統合・削除できる。
5. 「拡張の管理」で「詳細」を開き、いつ動くか、何が起きるか、使用する権限を読む。提供を停止している拡張の説明も読める。一覧に戻り、「提供中」または「停止中」のスイッチを押すと、提供範囲や影響が表示される。「キャンセル」で戻る。
6. 「設定」→「全体の設定」→「API トークンの管理」で、権限が「閲覧」「閲覧・下書き」「閲覧・下書き・会話の管理」に分かれていることを確かめる。

確かめること: 相手のデータを、期間で消すことも、相手単位で消すこともできる。AI に渡す権限を、下書きまでに絞れる。

## 11. プロジェクトの画面から問い合わせる（3分）

W3 · 通しのテスト H11、埋め込みチャット。

1. `pnpm dev:widget` を起動する。別のデモが起動中なら `HELPDESK_DEMO_PORT=8798 HELPDESK_PRODUCT_PORT=4174 pnpm dev:widget` のように空いているポートを指定する。表示された製品側のURLで「ヘルプ」を開く。
2. 「質問」に「領収書を発行したい」と入力し、「質問する」を押す。提示された「領収書を発行する」を開いて読み、チャットに戻る。
3. 「解決しなかった」を選び、返信先を入力して「送信」を押す。受付番号と返信先を確認する。
4. 運営側の受信箱からその番号を開く。「関連情報」の「チャットを開いたページ」に、製品側のサイトと `/billing/receipts` が表示される。

## 12. 記事を書き、問い合わせの前に解決できたかを見る（4分）

W3・W4 · 通しのテスト H12、記事の公開から解決率まで。

1. 見本用の運営画面で「ヘルプ記事」→「記事を書く」を開く。Slide を選び、題名を「共有リンクを作成する」、要約を「編集画面から閲覧用の共有リンクを発行できます。」とする。本文にリンクの発行手順を書き、「公開する」を押して内容を確認する。
2. 利用者のチャット `/help/chat/slide` を別タブで開く。「共有リンクを発行したい」と入力して「質問する」を押す。新しい記事を開き、手順を読んで「やりとりに戻る」→「解決した」を選ぶ。
3. 運営画面の「対応状況の集計」で「待たずに解決できた割合」を見る。新しいデモでこの手順だけを行うと、1件の提示のうち1件が解決する。記事一覧ではその記事の提示と閲覧も確認できる。

問い合わせフォームで試す場合は、[Slide の窓口](http://127.0.0.1:8788/help/form/slide)に「領収書を注文履歴から発行したい」と入力する。「この記事で解決しませんか」から記事を開き、解決できたら記事の「はい」を押す。元のタブで「送信せずに終了」を選ぶと、Slide の記事一覧へ戻る。解決の記録は残り、問い合わせは作成されない。

ローカルの見本は決まった確率を返すので、同じ手順を繰り返せます。実際のモデルでの記事選択の質は[日本語評価手順](reports/suggest-eval.md)で測定します。

## 13. 改善につなげる（5分）

W4 · [デモでの通しテスト](../tests/ux/demo-issues.pw.mjs)。`pnpm dev:demo` または `pnpm dev:widget` で起動し、[課題の一覧](http://127.0.0.1:8788/issues)を開く。ポートを変えた場合はターミナルの運営者URLを使う。

新しいデモには、開いている課題（声3件）、直した課題（2件中1件が未通知）、全員に知らせた課題（2件中2件）がある。「請求明細のダウンロードを改善する」を開くと、修正前と修正後の声が各1件ある。起票先は両方とも設定済みで、ローカルの模擬 GitHub を使う。[Slide の起票先](http://127.0.0.1:8788/extensions/issues?product=slide)・[Desk の起票先](http://127.0.0.1:8788/extensions/issues?product=desk)

| 手順 | 操作と確かめる結果 |
| --- | --- |
| a. 起票する | [会話 SLD-1](http://127.0.0.1:8788/conversation/1)の関連情報で「課題を起票する」を押す。狭い画面では先に「関連情報」を開く。「タイトル」に「領収書を注文番号で検索する」、「公開する要約」に「請求履歴に注文番号の検索欄を追加する。」と入力する。「起票内容を確認」で投稿先・要約・問い合わせ番号を確認し、「確認した内容で起票」を押す。公開する本文は要約と問い合わせ番号だけです。 |
| b. 別の声を紐づける | [会話 SLD-5](http://127.0.0.1:8788/conversation/6)の関連情報で「既存の課題を選ぶ」を開く。「題で探す」に先ほどのタイトルを入力し、「既存の課題と紐づける」を押す。確認画面でも同じボタンを押す。紐づけはデモの中に保存される。 |
| c. 件数を確かめる | [課題の一覧](http://127.0.0.1:8788/issues)の「開いている」で、作った課題の「声」が1件から2件になったことを確認し、タイトルを開く。「紐づく声」に SLD-1 と SLD-5 が並ぶ。 |
| d. 課題を閉じる | 詳細で「課題を閉じる（デモ用）」を押す。模擬 GitHub の課題が閉じ、一覧の「知らせる待ち」に「2件の声のうち2件にまだ知らせていません。」と表示される。 |
| e. 下書きを作る | 「知らせる待ち」で同じタイトルの横の「下書きを作る」を押す。「紐づく声」で2件とも「承認待ち」と表示される。この時点の「知らせた」は0 / 2。一覧に戻ったら「承認待ち 2件を確認する」で同じ下書きを開ける。 |
| f. 承認して知らせる | 「紐づく声」から SLD-1 を開く。知らせの下書きで「承認して送信」を押し、宛先と文面を読み、確認画面でも「承認して送信」を押す。「送信済み」になったら一覧で「知らせた」が1 / 2になったことを確認する。SLD-5 でも同じ操作を行う。2 / 2になると、この課題が「知らせる待ち」から消える。メールは模擬配送される。 |
| g. 改善率を見る | [対応状況の集計](http://127.0.0.1:8788/metrics)で「すべてのプロジェクト」「過去30日」の「声が改善に届いた割合」を見る。新しいデモでこの章だけを試すと、30%（3件 / 10件）から50%（5件 / 10件）になる。 |

承認後も、送信予定の間は会話の「取り消す」で編集済みの本文を承認待ちに戻せる。「アカウント」の「返信を取り消せる時間」で10秒、30秒、1分、5分を選べる。プロジェクトの設定の下限がより長いときは、その下限まで待つ。

課題の詳細からまとめて承認する場合は、「知らせの下書きを承認」で宛先と本文を読み、送る相手だけにチェックを付けて「選んだ下書きを承認して送信」を押す。文面を直す場合は「会話で文面を編集する」を開く。

手順 a の確認画面で書き直したいときは「入力内容を修正する」を押す。入力したタイトルと要約から再開できる。修正後にもう一度「起票内容を確認」を押して公開する文面を読む。手順 b の確認を「キャンセル」したときも、検索語と選んだ課題はそのまま残る。

## 振り返り

次の3つに「はい」と答えられれば、指針どおりに動いています。

- 相手は、普通のメールとして返事を受け取れたか。
- 送るかどうかを、最後は人が決めたか。
- 答えたあとに、記事にするか、直すかへ進めたか。

引っかかった箇所は、番号と手順をメモして、次の直しの材料にします。

## 14. プロジェクトごとにメンバーを分ける

デモでは佐藤 優が全体の管理者です。森 直子は Slide の管理者と Desk の担当者を兼ね、伊藤 蓮は Desk だけを担当しています。

1. [Slide のメンバー](http://127.0.0.1:8788/settings/projects/slide/members)を開き、「所属するメンバー」で佐藤と森の役割を確認します。[Desk のメンバー](http://127.0.0.1:8788/settings/projects/desk/members)では森が担当者になり、伊藤も表示されます。
2. Slide に戻り、「運営者を名前で検索」に「伊藤」と入力して「検索」を押します。「追加する役割」で担当者を選び、「メンバーに追加」を押します。Slide の会話で担当を変更するときに伊藤を選べます。
3. Slide のメンバー一覧で伊藤の「編集」を開き、「メンバーから外す」を押します。確認画面に出る担当中の会話件数を読み、もう一度「メンバーから外す」を押します。Slide で伊藤が担当していた会話は「担当なし」に戻り、Desk の担当は続きます。
4. 初めて参加する人には「招く人のメールアドレス」と「招く人の役割」を入力して「招待する」を押します。一覧には「招待中」と表示されます。その人が Cloudflare Access を通って初めてログインすると、招待したプロジェクトを開けます。
