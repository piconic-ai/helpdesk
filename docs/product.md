# helpdesk

運営者はひとつの受信箱で返信が必要な会話を見つけ、その会話の窓口アドレスから相手に返信します。窓口と担当者をまとめた単位を「プロジェクト」と呼びます。製品のサポート、カンファレンスの1回の開催、コミュニティの運営をそれぞれ1つのプロジェクトとして扱います。

運営者は所属するプロジェクトの会話を担当します。プロジェクトの管理者はその窓口やメンバーを設定し、全体の管理者はプロジェクトの追加・保管と、デプロイで提供する拡張を決めます。提供された拡張を使い始めるかは、各プロジェクトの管理者が決めます。同じ人が、あるプロジェクトでは管理者、別のプロジェクトでは担当者になることもできます。

## 利用場面

会話を通じて問い合わせに答え、利用者の声を記事や改善に反映します。履歴を使って、解決までの時間、一回で解決した割合、担当者の作業時間、改善につながった割合を振り返ります。自動返信には自動送信と明記し、エージェントが書いた返信は運営者が承認します。

運営者が複数の相手と同じ段取りで個別にやりとりする場面も対象です。カンファレンスのスピーカーやスポンサー、ベータ版の参加者、障害の影響を受けた人への連絡が該当します。

**W6 まとめて進める**は段階03・04の計画です。相手を選び、同じ連絡を個別の会話として始めます。返事を一人ずつ受け取り、段階を進め、全員の進み具合を見渡します。[実装の段階と完了条件](plan/next/00-overview.md)

## 作らないもの

- 宣伝や購読のための一斉配信。関係のある相手との個別の連絡をまとめて始める機能は、段階03で実装を予定しています。
- 汎用のメールソフトや顧客管理。相手への目印や宛先リストも段階03の対象です。
