# 実装方針

単一の Worker が HTTP、メール、キュー、定期処理を受け付けます。会話の判断に必要なデータを読み出し、純粋関数が次の状態を決め、D1 の batch で会話と出来事を書き込みます。メールの原文と添付は非公開の R2 に置きます。

操作は名前、スキーマ、権限、手続きの組で登録します。運営画面と外部のクライアントは同じ操作を呼びます。拡張は静的に登録し、核のテーブルへの書き込みは核の手続きを通します。

[層ごとの依存規則と状態の定義](../plan/03-design.md)・[拡張の契約](../plan/stage-2-extension-points.md)

## 送信予定と会話の完了

操作で承認した返信には D1 の送信予定と outbox の試行が紐づきます。受信処理が人からの新しいメッセージを記録すると、同じトランザクションで未送信の予定を下書きに戻し、停止理由と元の承認者を出来事に残します。Queue の配送側は outbox の行を一度だけ取得します。配送が先に始まった場合は結果の確定を待ちます。

「送信して完了」の状態変更と完了時刻は、メールサービスが送信を受理してから保存します。解決アンケートはこの完了の出来事を受け取ります。
