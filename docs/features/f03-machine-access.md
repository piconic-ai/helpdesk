# F03 運営者の代理で問い合わせを扱う

## 利用場面

運営者がターミナルや MCP クライアントから未対応の会話を調べ、返信案を用意する。

## 得られる結果

会話の操作が運営画面の記録に残る。運営者は下書きを読み、送信を承認できる。

## 体験の流れ

1. 運営者がトークン画面で、閲覧または下書きの範囲を選んでトークンを発行する。
2. CLI または MCP クライアントが、そのトークンで使える操作を取得する。
3. 返信の下書きを付け、運営者が内容を確認する。使い終えたトークンは失効できる。

## 作る範囲

HTTP API の操作一覧・入力・出力、CLI の操作発見と実行、Streamable HTTP の MCP ツール、トークンの発行・失効と代理操作の記録。

## 作らないこと

エージェントに運営者の承認を代行させること。

## 受け入れ条件

- **F03-AC1** MCP から未対応一覧を取得し、返信案を付けると承認待ちになる。
- **F03-AC2** 閲覧用トークンによる下書きは拒否される。
- **F03-AC3** 操作記録でトークンの識別子と代理された運営者を確認できる。
- **F03-AC4** CLI の成功時の --json 出力は JSON で、失敗時には標準エラーと非ゼロ終了を返す。
- **F03-AC5** 失効したトークンで操作一覧にアクセスできない。
- **F03-AC6** HTTP API と MCP の応答でメール本文を信頼できない入力として識別できる。

## 未決事項

本番の Access ポリシーと各 MCP クライアントの接続設定は運営者が確認する。
