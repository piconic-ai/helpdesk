# 画面の型と共通部品

受信箱から設定に移っても、見出し、条件、操作、結果を同じ場所で探せるようにした。開発専用の見本を先に作り、1440・1024・375pxで表示と操作を確かめて撮影した。その後に運営画面と公開ヘルプを移行した。[全画面の変更前後と部品の見本](index.html) · [元の指摘](../../plan/ux-fixes-3.md)

| 対象 | 対応と確認した操作 |
| --- | --- |
| 受信箱 | 差出人を先頭に、件名を続け、製品を控えめなチップにした。既読の太字を外し、選択欄を行の中央に揃えた。右端は時間と担当者、2行目は要約・印・ラベルとした。単一状態の一覧では同じ状態を繰り返さず、複数の状態を扱う一覧では表示する。日本語変換中の入力を待って検索し、条件のチップから解除できる。 |
| 会話と返信 | 状態・担当・ラベルの選択を枠のない属性の行に集めた。担当者の候補には写真かイニシャルと選択印が付く。見出し右の操作と矢印で前後の未対応に移れる。返信とメモは、タブ、入力欄、確認・送信を一体にした。 |
| サイドバー | 共通の運営ナビと、個人のアカウント操作を分けた。個人のメニューか「?」キーでキーボード操作を開ける。API トークンの固定項目を外し、記事と集計に異なるアイコンを使った。 |
| ヘルプ記事 | 行に題、製品、公開状態、更新日、役に立った割合を表示する。公開記事の検索は、製品別・横断の両方で検索語を維持して20件ずつ移動できる。検索結果がなくても問い合わせ先に進める。 |
| 設定・編集 | 設定の行全体から移動でき、窓口数、運営者数、トークン数、保存期間は保存済みデータから表示する。連絡先と会話を消すデータ管理を別の区画に置いた。編集欄の保存、取り消し、他のフォームの下書きの保持を確認した。 |
| 集計 | 製品と期間を1行で切り替える。375pxでも任意の日付範囲を開いて入力できる。解決までの平均時間を先頭に、一次解決率と平均作業時間を並べた。各カードに定義と前期差、比較に必要なデータが欠ける場合はその理由を表示する。 |
| 拡張 | カードに題、説明、切り替え、設定への入口をまとめた。権限の内訳は有効化の確認と各拡張の設定で読める。切り替えの取り消し、権限のない運営者の拒否、複数の管理者が続けて変更した場合も検証した。 |
| 公開ヘルプ | フォーム、問い合わせの控え、チャット、記事、アンケート、エラーに同じ4種類の型を使う。記事の評価や相談への引き継ぎでは、選んだ回答や質問、次の窓口を表示する。 |

## BarefootJS と追加した部品

`pnpm exec bf docs <部品名>` と公式カタログで Button・Input・Textarea・Native Select・Popover・Dialog・Dropdown Menu・Tabs・Tooltip を確認した。BarefootJS UI の MIT ソースをもとに、Hono のサーバー描画に合わせたスロット、デザイントークン、ネイティブのフォーム送信とトップレイヤーに対応させた。タブとツールチップは BarefootJS のクライアントコンポーネントで動く。[BarefootJS UI](https://ui.barefootjs.dev) · [参照したソース](https://github.com/piconic-ai/barefootjs/tree/5ce2855c5/ui) · [ライセンス](../../../src/ui/BAREFOOT-LICENSE)

4つの画面の型、件数と操作を持つ見出し、条件と解除チップ、問い合わせ行、設定行、数値カード、属性と操作の帯は、ヘルプデスクのデータを組み立てる部品として追加した。メール・内部メモ・記録、返信する相手、担当者の印、拡張の権限は、このアプリの状態から表示する。見本で確認できる状態は、通常・選択・既読、空・読み込み中、入力エラー、保存・無効、ポップオーバー・メニュー・確認・フォーカスを含む。[共通部品](../../../src/ui/patterns.tsx) · [フォームと操作](../../../src/ui/controls.tsx)

## 検証の範囲

- 全画面の構造検査では、画面ファイルの JSX と HTML 文字列を読み、要素への装飾の直書きと部品を経由しない表示用コントロールを検出する。ブラウザでも各画面に型があることを確認する。[構造検査](../../../scripts/page-composition.test.mjs)
- 各幅で見出し・本文の左端、カードの余白、リストの点、移動リンク、枠付き操作の連続、はみ出し、フォント、アクセシビリティを検査する。キーボード、押下、無効、150ms のフェード、動きを減らす設定は実ブラウザで確認する。[描画の検査](../../../tests/ui/composition-audit.mjs)
- 修正前は `e0725d0`。既存の74画面・状態にはそのコミットで検証済みの画像を再利用した。追加した10場面は同じ変更前のアプリで撮影した。比較ページでは各幅の画像を選んで原寸で確認できる。
- 公開記事本文の箇条書きと文章内リンクは、著者の構造を保つ。受信した HTML メールは隔離したフレームで描画する。添付ファイルの応答、外部向け JSON API、Cloudflare Access のログインはアプリの画面テンプレートの対象外とした。
- 更新日時を記録する前の記事は「更新日未記録」、評価がない記事は未評価として扱う。ローカル検証には Chromium と Worker・D1・R2 を使い、外部のメール配送・GitHub・AI はテスト用サービスを使った。

## 再現

`pnpm build` の後、`pnpm dev:demo` のローカル URL で受信箱と `/dev/ui` を開ける。見本は開発環境のみで提供する。見本の画像は `node tests/ui/gallery-capture.mjs`、画面比較用の画像は `HELPDESK_DAILY_CAPTURE=docs/reports/ux-3/after pnpm test:ui` で収録し、`node tests/ui/composition-report.mjs` で比較ページを生成する。通常の `pnpm test:ui` は保存済みの画像と比較する。通しの操作は `pnpm test:ux`、コードとカバレッジの検証はプロジェクトの手順に従う。[検証手順](../../plan/05-verification.md)
