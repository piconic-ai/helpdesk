## ブラウザーで再現した問題

- 375・1024pxの課題の紐づけ確認で、開いていた関連情報パネルが消えた。元のパネルの外にあるダイアログを開くと、ブラウザーがポップオーバーを閉じていた。同じパネルを開いたまま確認し、キャンセル後に検索語と操作位置を保つことを通しテストに加えた。
- 375pxで会話 #4 を開くと、先行する返信の送信失敗が返信欄の下に隠れた。件名近くに「送信失敗の返信へ」を表示し、失敗理由と「再送」に移動できるようにした。会話 #2 の送信済み返信と #3 の内部メモでも対象に移動できる。実際に移動した位置で本文が操作帯と返信欄に覆われていないことを検査した。
- 公開前の確認で要約を書き直す入口が分かりにくかった。「入力内容を修正する」で入力済みの文面に戻り、再度確認できるようにした。Slide では会話の確認ダイアログ、Desk では JavaScript を無効にした通常の確認ページを使った。どちらも最終確認より前に模擬 GitHub への投稿がないことを確認した。

## 検査と残っている指摘

第13周の撮影中に、集計の選択中ラベルが淡く表示されることが分かった。関連16件の再撮影・表示検査を通した後、全254件の通常の画素比較が合格した。5業務34シナリオを含む全139件のブラウザー検査、332件の単体・結合検査、拡張有効・無効で各66件の受付検査も通った。その後に行った上記の修正では、失敗を再現した3件の通し検査がすべて合格した。[5業務の操作記録](round-13/verified/walk.md)・[比較画面](index.html)

狭幅の一覧での時刻・担当・選択欄の位置、集計ナビ2項目の識別、通知が本文や宛先を隠す場合、ラベル色、起票フォームと比較対象の課題名、公開窓口の利用範囲、通知先やルールの初期値などは、各担当の「実際」と「期待」に記録した。次の検査で修正前後を照合する。高・中が続けて0件という終了条件は未達。

修正後の全件確認では、Esc が確認画面の背後のメニューにも作用する問題を再現し、一番手前のダイアログがキーを受け取るようにした。公開フォームの再送時に件名の位置が異なる検査も1回失敗したが、個別と全件の再実行では再現しなかった。最後の通し検査は141件、単体・結合検査は332件、拡張の有効・無効を切り替えた検査は各66件が合格した。
