## 第1〜6周で検証した部品と振る舞い

- 確認ダイアログで、これから行う操作と対象を読めるようにした。拡張の有効化・無効化、会話の統合、振り分けルールの削除を個別の対象で検証した。
- 返信では、明示的に拒否された場合と、記録後の通信断で結果が不明な場合の案内を分けた。結果不明なら下書きを残し、送信結果を別タブで確認できる。キーボードで返信と内部メモを切り替え、メモが会話の内部に残ることも確認した。
- 一覧と集計の条件指定を、小さい画面でも用途に合う幅に整えた。長い製品名を選んだ集計と、入力の前に絞り込み条件を持つ受信箱の両方をテストした。
- 公開窓口では送信前に推薦記事と入力内容を読み、記事を評価した後でも手順を開き直せるようにした。自動メールは適用範囲と製品別の送信例を明示し、保存した文面とローカルの配送結果を照合した。

## 第6周の時点で残した軽微な点

| 画面・幅 | 残したものと理由 |
| --- | --- |
| 送信に失敗した会話一覧・375px | 警告・請求ラベル・担当が並ぶと一部の差出人が「渡…」になる。件名と番号を読み、会話を開けば氏名とアドレスを確認できる。 |
| 記事候補のない会話・1440px | 返信欄と関連情報に「記事の候補に追加」がある。同じ会話への操作で、狭幅では返信欄の入口を使える。 |
| 迷惑メール一覧・375px | 本文抜粋の末尾を省略する。件名・差出人は読め、会話で全文を確認できる。 |
| 埋め込みコード・375px | 長いコードの末尾は欄内を動かして確認する。コピー操作でコード全体を取得できる。 |
| 書き出し・375px | 「操作履歴12件」が語の途中で折り返す。件数と対象が表示され、書き出し内容を確認できる。 |
| 候補からの記事編集 | 元の会話と記事のカード外枠が接する。両方に見出しと内側の余白があり、参照と編集を識別できる。 |
| 解決時間の操作結果と集計 | 同じ例を操作結果は5,760分、集計は4日で示す。数値は一致し、画面をまたいで比べるときに換算が必要になる。 |
