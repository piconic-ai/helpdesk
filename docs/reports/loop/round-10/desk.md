# 会話・受信箱の独立画面レビュー

114状態を375、1024、1440pxの順に比較した（計342画像）。参照は指定されたPNG、DESIGN.md、criteria.md。各識別子に「-375.png」「-1024.png」「-1440.png」を付けると元画像名になる。以下は、その画像で読める情報と位置についての判断。ホバーの説明、キー操作の実行、外部への送信、内部の承認履歴、処理時間は静止画で検証できない。

全画面を並べて見ると、一覧では検索・選択・行の順が共通し、会話では本文と返信を左、関連情報を右に置く構成が繰り返される。黄色の内部メモ、赤い配信エラー、薄青の一括選択は縮小しても区別できる。一覧の情報量が増えたときは、とくに375pxでこの整列が崩れる。

## 指摘

|番号・重さ|対象幅・状態|実際に見えること|基準・期待|
|---|---|---|---|
|D1・中|375・1024px。inbox、all-inbox、approval-list、loop-bulk、my-inbox などの受信一覧|375では製品・人名、件名・時間、抜粋、印・担当が別段になる。inbox の #11 は約150px、#7 は128px。#7 の未割当の円だけが左下に残る。1024でも通常の行が約106pxで、氏名、件名、抜粋が3段。|DESIGN の会話行・レスポンシブ、基準の順位・揃え・幅。件名と抜粋を2行で追い、時刻・担当者を別の会話と同じ右端で見比べたい。|

### 画像だけでは原因を特定できない差

R1（高の見本との照合が必要）。375px の thread-approval と approval-confirm の比較で、Helpdesk 下の水平線の y 座標が46から35に変わり、件名と下書きも約11px上へ移る。1024、1440pxの同じ組では背景位置に差は見られない。375では確認前の承認ボタン自体が画面下端に掛かっている。クリックに伴う事前スクロールと、ダイアログが開いた時のずれを静止画から区別できない。開く直前と直後を同じスクロール位置で比較し、後者の場合は基準の高に当たる。

## 各状態の原記録

各行の観察は左から375／1024／1440px。メニューの重なりで隠れた内容は、同じ状態のほかの幅で可視の範囲を記した。

### all-inbox

運営者が製品や状態をまたいで先に扱う会話を決める。

- 範囲は？→すべてのプロダクトの10件。
- 先頭は？→11時間待ちの #11。
- 緊急な例は？→#4 に赤い送信失敗、#5 に承認待ち。

375px：375では長い会社名と担当者名で2行、印は下へ続く / 1024px：1024では件名が氏名の次段に並ぶ / 1440px：1440では各行右側の状態で混在を判断できる。 関連指摘 D1。

### approval-confirm

運営者がエージェントの返信内容と送信先を最終確認する。

- 誰に届く？→customer5@example.net。
- 何が届く？→更新時のメンバー数変更を案内する文。
- どう確定する？→「承認して送信」、隣にキャンセル。

375px：375では背景のヘッダー線が通常画像より11px上にある / 1024px：1024では通常画像と件名・サイドバーの位置が一致する / 1440px：1440でも背景を暗くし白い確認枠を中央に置く。 関連指摘 R1。

### approval-list

- どの会話？→Slide の契約更新 #5。
- 何を読む？→「下書き」と冒頭文、橙色の承認待ち。

375px：375では担当未指定の円が左下に1行を占める / 1024px：1024では宛名・件名・下書き抜粋が縦3段 / 1440px：1440では「下書き」と「承認待ち」が同じ会話に見える。 関連指摘 D1。

### composer-empty

375px：375では通知が本文の後半に重なり「閉じる」が読める / 1024px：1024では通知が入力枠の下に重なる / 1440px：1440では本文と再確認先が同時に見える。
