## 指摘を受けて直した箇所

- **受信箱**　375pxでは番号・経路・最新の文を一段、ラベル・担当者・クイック操作を別の段にした。修正前の先頭行では、本文に割り当てられる幅が約13pxだった。修正後のブラウザー検査で、各行の抜粋に110px以上あり、担当者と操作ボタンが重ならないことを測る。一括担当メニューは選んだ会話の現在の担当者にチェックを付ける。条件に合う会話がない場合は説明を先に表示する。
- **課題と関連情報**　会話選択では番号とプロダクトを1行に保ち、件名を次の段に表示する。「記事候補を書く」「比較する期間を選ぶ」と実行ボタンの文言を分けた。課題を開く・探す・紐づける操作は「課題」に統一した。
- **選択欄と管理画面**　空のラベル絞り込みは「すべてのラベル」、保存期間の丸は各選択肢の左に表示する。ラベル表は名前に2行を割り当てた。拡張のカードは同じ行で見出し・説明・設定操作の位置を揃える。
- **設定案内**　GitHub の接続用トークンの状態を通常の言葉で示した。シークレットの名前とメール通知の設定例は接続手順を開いて読む。書き出しの内側の見出しは「対象と個人情報の扱い」にした。

承認画面の375px画像には、開く前後で11pxの位置差が見えた。元の画像では承認ボタンの下端が画面外にあり、クリックのためのスクロールか、ダイアログ自体の移動かは画像から判別できない。ブラウザー検査では先にボタンを画面内に置き、押す直前と表示直後の縦横スクロール量、件名の上端を比較する。[操作テスト](../../../tests/ui/review-thread.pw.mjs)

軽微な指摘として、画像ファイル選択のブラウザー言語、日付の改行、広いチャット内の問い合わせボタンの幅、記事末尾の案内、期間入力の間隔がある。各状態の詳細は原記録に記載した。[画像](round-8/screens/)・[初回の操作記録（途中で停止）](round-8/walk.md)・[修正後の全手順と所要時間](round-8/retry/walk.md)

初回はハンズオンで既存の課題を選ぶ手順が停止した。検索欄の初期化前に開いた場合も候補を取得し、目的の課題を題名で選ぶようにした。全件実行と手順記録の出力先指定が別々だったため、後から手順別の記録を再取得した。追試には第9周以降の修正も含む。

返信欄の初期化中に「記事を添える」を開くと、候補を選べても本文にリンクが入らないケースを追試で再現した。記事を選択できる時点を初期化完了後に揃え、通信を意図的に遅らせた回帰テストと、上記の29テスト（34件の手順記録）の再実行で確認した。
