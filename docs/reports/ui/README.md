# Helpdesk 画面レビュー

[変更前と変更後の全画面](index.html)を左から右に比較できます。右側には操作性改善後の画面を載せています。[場面別の操作記録](../ux/index.html)では、同じ会話で操作を続けたときの流れを確認できます。画像を選ぶと原寸で開きます。[受信箱と会話の途中比較](interim/index.html)には、一覧と会話を実装した時点の2画面を保存しました。

## ローカルで試す

Node.js 24 で `pnpm install --frozen-lockfile`、`pnpm dev:demo` を順に実行してください。[受信箱](http://127.0.0.1:8788/)に例示データが11件あり、既定の未対応ビューには7件が並びます。[会話の返信欄](http://127.0.0.1:8788/conversation/1)、[フィードバック](http://127.0.0.1:8788/help/feedback/slide)、[ヘルプチャット](http://127.0.0.1:8788/help/chat/slide)も操作できます。チャットでは「領収書はどこから発行できますか？」で記事を提示し、「契約名義を変更できますか？」で問い合わせの連絡先入力に進みます。

デモはループバックで動作します。D1・R2・Queues はローカルの Worker ランタイムを使用し、メール送信と AI 判定は固定の応答で再現します。停止すると例示データに対する変更は消えます。保存して開発するには[Wrangler の手順](../../dev/development.md)を使用してください。

[画面の一覧](../../../tests/ui/screens.mjs)と[シード](../../../tests/ui/seed.mjs)に再現条件をまとめています。日付・乱数・言語・タイムゾーン・ピクセル倍率を固定し、独立したデータベースで起動します。基準環境は macOS 26.6.2 arm64、Playwright 1.64.1 の Chromium です。CI のブラウザ検証は macOS 26 を使います。OS の日本語フォントが変わると文字のピクセルに差が出るため、差分を確認してから画像を更新してください。

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
pnpm test:ui
```

通常の比較では画像を更新しません。意図した変更を反映する場合は `pnpm test:ui --update-snapshots=all`、一覧ページを再生成する場合は `node tests/ui/report.mjs` を実行してください。変更前は `0787488ea5b0121d2f3a83c801befe97d8038e6b` を別ディレクトリに展開してビルドし、現在の作業ディレクトリから `HELPDESK_UI_BEFORE=/path/to/checkout pnpm test:ui` で撮影できます。

## 部品と判断

- [DESIGN.md](../../../DESIGN.md)に設定用の `settings-card`、削除確認用の `dialog`、一覧の読み込みを示す `loading-placeholder` を追加しました。共通寸法を `layout` にまとめ、選択状態でも薄い文字が読めるように `muted` を調整しました。
- 設定の削除では対象のメールアドレスを確認ダイアログに表示します。比較の左側は旧版で削除直前に入力できたフォームです。
- 旧版のチャット、フィードバック、問い合わせフォームは API で受付を提供していたため、新しい入力ページと同じ URL では実際の404を、受付結果では旧 API に同じ内容を送った実際の JSON を載せました。
- 通知、自動受付返信、振り分けルールの画像は、管理画面で拡張を有効にした状態です。外部サービスへの配信可否は、この画面の検証対象に含めていません。
- 公開の受付画面は5秒後に強調を解き、受付番号は読み返せるように残します。右側の画像は受付直後です。
- フィードバックは既存の受付処理で有効なメールアドレスを必要とします。公開画面でも入力を必須にしました。DESIGN.md にある匿名での送信を扱うには、連絡先の保存と問い合わせへの変換の仕様を決める必要があります。
- HTML メールは隔離したフレームに表示し、外部画像を遮断しています。現行の受け入れ条件 F01-AC15 を維持するため、DESIGN.md にある外部画像の表示ボタンは保留しました。

## 人の目で見てほしい点

- 375px の受信箱で長い件名、状態、送信失敗を見分けられるか。会話を開いた後、最後の行までスクロールして返信欄と本文を読み分けられるか。
- 返信と内部メモの背景・注記・ボタン名から、相手に届くかを判断できるか。
- 公開チャットで記事を提示する場合と、連絡先を聞いて問い合わせにする場合の次の操作が伝わるか。

本番の Cloudflare Access、メールの到達性、実際の Workers AI の応答は、[運用環境で行う確認](../../plan/05-verification.md)を参照してください。
