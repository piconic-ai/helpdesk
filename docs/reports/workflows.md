### 判断に迷う表示と該当手順

操作の所要時間は上記の各手順に記録した。以下は画像から複数の解釈ができた箇所と、操作中に確認し直した箇所である。自動テストの操作時間は、人が判断に使った時間には換算していない。

| 業務・手順 | 確かめ直した点 | 変更と記録 |
| --- | --- | --- |
| W1・受信箱から返信を開く | 失敗した別の返信の印が、直近の送信済み本文を指すように見えた。 | 発言者と配送状態を会話履歴と照合した。[第9周](loop/round-9.md) |
| W1・返信に記事を添える | 記事を選んだのに本文にリンクが入らず、もう一度選ぶ必要があった。 | 読み込みを遅らせて再現し、選択できる時点を修正した。[第8周の追試](loop/round-8.md) |
| W2・送信をやり直す | エラーの帯が挟まり、直前に入力した欄と再送する場所が動いた。 | 入力位置と再送先を検査する。[第10周の公開窓口](loop/round-10/public.md) |
| W3・会話から記事を書く | 編集時の改行と公開時の改行が異なり、読者が見る本文を比較し直す必要があった。 | 同じ本文構造とスタイルで表示する。[第9周](loop/round-9.md) |
| W4・作る課題と通知を確認する | 起票した事実と、顧客に知らせを送った事実を区別するため、通知の作成者と承認者を確認した。 | 下書きと承認済みの履歴を区別し、実際の承認記録から表示する。[第10周の会話](loop/round-10/desk.md) |
| W5・窓口を登録する | 自動送信の承認文の機能名が拡張一覧と異なり、承認の対象を見直す必要があった。 | 一覧の名称を共用し、窓口の登録前に条件とともに表示する。[第10周の設定](loop/round-10/settings.md) |

第12周では検索語を選び直した直後の読み込みと、返信プレビューの初期化を遅らせて操作した。検索語の前に古い語が残る現象と、プレビューの最初のクリックが無効になる現象を再現した。通常の会話と承認つきの会話の両方で、送信の手順を再検証した。[第12周の記録](loop/round-12.md)

第13周では、5業務34シナリオを含むブラウザーテスト139件が通った。「改善につなげる」は会話 #1 から起票し、#6 を紐づけた。2件の下書きを用意した直後は改善率が30%のままで、会話ごとの承認・模擬配送を経て50%になった。初回の通し検査では受信箱の待ち時間を二重に描画しており、再検査では拡張の記号が画面間で異なった。時刻はそれぞれの会話行に1つ、拡張の記号は全画面で同じになるように修正した。[初回](loop/round-13/walk.md)・[再検査](loop/round-13/retry/walk.md)・[修正後の操作記録](loop/round-13/verified/walk.md)

第14周では、5業務の34シナリオを含む全142件のブラウザー検査が通った。公開受付では、Slide の「埋め込み先を編集」からサイトを登録し、返信の目安を保存・取り消し・再保存した。登録サイトのチャットで「2営業日以内」を読み、登録を解除するとそのサイトからの表示が拒まれるところまで確認した。会話では、375pxの保存通知と送信の取り消しが宛先やタブを覆わないことも検査した。[第14周の操作回数と表示待ち](loop/round-14/verified/walk.md)

第15周の34シナリオはすべて合格した。別の返信の承認が必要な会話では、一覧で「別の返信が承認待ち」を読み、詳細から対象の下書きへ移れる。送信受付の直後に通信が切れたケースでは再読み込み先で1件の返信を確認した。公開する課題は、入力を一度閉じて開き直しても要約を保持し、確認を終えて初めて模擬 GitHub に届く。これらを含むブラウザー検査144件が通った。[第15周の操作回数と表示待ち](loop/round-15/verified/walk.md)
