# 指針レビューとハンズオンの結果

受信箱に届いた声を、課題・記事・改善後のお知らせまで追えるようにした。運営者「佐藤 優」と利用者の両方を、例示データのローカル Worker で操作した。[変更前後と操作画像](index.html) · [レビュー原本](../../plan/review-4.md) · [ハンズオン](../../plan/hands-on.md)

## A　改善につなげる操作

| 指摘 | 実装とブラウザで確認した結果 |
| --- | --- |
| 1　課題 | サイドバーの「課題」に、題・プロダクト・開閉状態・紐づく会話・知らせた件数を表示する。閉じた課題の操作でお知らせの下書きを用意し、担当者が会話で承認すると配送に進む。修正の前後30日で、その課題に関係する会話がプロダクトの声全体に占める割合を分子・分母つきで比較する。「目安」と明記し、修正後は観測できた日までを数える。[課題と通知](index.html#walk-review-4-issues) |
| 2　指標 E | 選択した期間に受け付けた問い合わせとフィードバックのうち、課題に紐づき、修正後の知らせが期間末までに送信成功になった会話の割合を表示する。1会話は1件として数える。迷惑メール、未承認の下書き、送信待ち、配達失敗は通知成功に含めない。期間内の声が0件なら「データなし」と表示する。[通知から集計まで](index.html#walk-review-4-issues) |
| 3　声の集計 | 受付日を日本時間で区切り、ラベル別・プロダクト別・月別に集計する。行を押すと期間と選択条件を維持した問い合わせ・フィードバックの一覧に進む。複数ラベルの会話はそれぞれのラベルに1件ずつ数える。[絞り込みと内訳](index.html#walk-review-4-voices) |
| 4　記事の候補 | ヘルプ記事の「候補」で元の会話を確認し、記事を書き始める。元メールの本文は公開欄に自動転記しない。下書きを保存した後は同じ候補から再開できる。[候補から編集](index.html#walk-review-4-voices) |
| 5　自動送信 | 自動受付返信と解決アンケートの設定で、承認した運営者・日時、実際の送信用テンプレートのプレビューを確認できる。文面を製品別に編集し、別製品の本文が変わらないこと、ローカルの配送内容が保存値と一致することを確認した。有効化日時のない旧データは「記録なし」と表示する。[両メールのプレビューと配送](index.html#walk-review-4-mail) |
| 6　起票設定 | リポジトリまたはトークンが未設定の場合は、会話内に不足項目と GitHub Issue 設定への入口を表示する。拡張一覧にも「設定が必要」と表示する。設定済みの窓口では、確認した要約から起票し、別の会話を既存の課題に紐づけた。[未設定から起票まで](index.html#walk-review-4-issues) |

## B　見た目と操作

| 対象 | 対応 |
| --- | --- |
| 確認ダイアログ | 開く直前のスクロール位置を保ち、キャンセルにフォーカスする。実行は右端の主ボタン。閉じると元の操作にフォーカスが戻る。375・1199・1200・1440pxで、開閉前後のページ位置と見出し位置を比較した。[承認の比較](index.html#screen-approval-confirm) |
| 承認待ち | 編集欄の下に「承認して送信」と「下書きを破棄」を横並びにし、承認を主ボタンにした。宛先と編集した本文を確認してから実行する。[操作記録](index.html#walk-J4) |
| 会話の関連情報 | 1200px以上ではタイムライン右側に固定し、狭い画面では見出しの「関連情報」から同じパネルを開く。リンク済みの課題・記事・過去の問い合わせ・履歴を確認できる。[パネルの比較](index.html#screen-thread-context) |
| 会話の操作 | 定型文を返信欄で選び、スヌーズの日時を「その他の操作」で指定する。Issue の起票は投稿内容を確認するダイアログを経由する。未割当の会話には「担当者を選ぶ」と表示する。[定型返信・保留・統合](index.html#walk-C-panels) |
| 拡張の管理 | 有効・無効は1行に保ち、長い題は省略表示する。区切りの見出しとカードの間をデザイントークン lg（24px）に揃えた。[管理画面](index.html#screen-extensions) |
| 対応状況の集計 | 比較期間の注記を条件帯の直下に置いた。上段に解決時間・一次解決率・平均作業時間を配置し、先頭の解決時間を強調した。件数は下段に置き、定義を短く表示し、詳しい説明をツールチップで読めるようにした。[集計画面](index.html#screen-extension-metrics) |
| 記事の一覧 | 題を行の主情報にし、プロダクト・更新日・評価の列を揃えた。狭い画面では補足を次の段にまとめる。[記事の一覧](index.html#screen-extension-articles) |
| 画面の切り替え | 文書遷移に重なっていたフェードを1回にした。実際に受信箱から設定へ移動し、ブラウザの animationend で150ms、終了時の不透明度1を確認した。動きを減らす設定ではフェードを省く。[ブラウザ検査](../../../tests/ui/review-thread.pw.mjs) |

## 再現

変更前の基準は `b293ae9`。既存の84画面・状態にはそのコミットで検証した画像を使い、追加の8場面は同じコミットをビルドして撮影した。新設ルートの変更前画像には当時の404や通常の新規編集画面が写る。手元で画像を更新するには、ビルド後に次を実行する。

```sh
HELPDESK_DAILY_CAPTURE=docs/reports/review-4/after pnpm test:ui
HELPDESK_UX_REPORT=1 HELPDESK_UX_STEPS=docs/reports/review-4/walk pnpm test:ux
HELPDESK_GALLERY_CAPTURE=docs/reports/review-4/gallery node tests/ui/gallery-capture.mjs
node tests/ui/review-report.mjs
```

検証には Chromium、Worker、D1、R2 を使った。メールソフトの受信箱への到達と表示、実在する GitHub リポジトリへの投稿、本番の Cloudflare Access はローカルの検証範囲外。[プロジェクトの検証手順](../../plan/05-verification.md)
