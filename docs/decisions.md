# 設計上の決定

- 問い合わせ番号は D1 がデプロイ全体で採番する。表示は `SLD-123`、件名は `[SLD-123]` とする。接頭辞は管理者が窓口の設定から英大文字2〜5字で設定する。移行時と新規登録時に重複しない初期値を割り当てる。返信は同じ差出人と窓口の条件で、古い接頭辞や `[#123]` からも通し番号でたどる。
- GitHub Issue の本文は確認済みの要約と問い合わせ番号を載せる。既存 Issue との紐づけは運営画面で保持する。
- 初回の運営者登録と権限の決定は同じ SQL 文で行う。Access の発行元、宛先、署名、有効期限とメールアドレスを検証する。[Access JWT の検証](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)
- 送信結果の Message-ID を保存し、返信には元メールの In-Reply-To と References を設定する。Cloudflare が受理したか不明な送信を自動で再試行すると二重送信になり得るため、確実に失敗した送信だけを再送対象とする。[送信 API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/)・[ヘッダー](https://developers.cloudflare.com/email-service/reference/headers/)

- Workers 上で postal-mime の解析と mimetext の MIME 組み立てを確認した。本番の送信は構造化 binding に本文を渡し、サービスに MIME の生成を委ねる。受信は先に原文を非公開の R2 に置き、キューで解析する。[受信ハンドラー](https://developers.cloudflare.com/email-service/api/route-emails/email-handler/)・[R2 の API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)・[キューの再配送](https://developers.cloudflare.com/queues/configuration/batching-retries/)・[D1 の batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)
- 保存期間は既定で無期限とし、検索は件名・相手・本文の部分一致を採用した。本文と添付を削除する際は R2 のキーを D1 に一時記録し、中断後は定期処理から削除を再開する。
- ローカル開発者は環境名とアドレスの両方を指定する。非ローカル環境で開発用アドレスを検出した場合は要求を拒否する。

- MCP は公式 TypeScript SDK の stateless Streamable HTTP を採用した。CLI と MCP は同じトークンと操作の定義を使う。発行した秘密は一度だけ表示し、D1 にはダイジェストを保存する。[MCP transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)・[Cloudflare の transport](https://developers.cloudflare.com/agents/model-context-protocol/transport/)
- 段階2で受付、操作、出口を各1種類実装した。権限を実行時に検査する context、各拡張のストレージ、パネルの選択肢とリンクを共通の口に追加した。issue を閉じた後に作る下書きには安定したキーを付け、定期処理の再実行による重複を防ぐ。

## 段階3の拡張契約

自動送信、一覧での保留、古い番号の解決、公開記事の閲覧、記事選択の判断、指標用の出来事の読み取りが必要になった。既存のフォーム・定型返信・issue 拡張の契約を保持し、追加の口は用途ごとに選択して使う。送信には `send` 権限と運営者が有効化した方針を必要とする。公開画面は運営者向けの認証から独立し、公開用のデータだけを返す。書き出しの既定値では自由記述に含まれる相手の情報も伏せる。

- スヌーズの期限はタイムゾーン付き ISO 8601 で受け取り、一覧取得時の時刻と比較する。期限どおりに再表示でき、定期ジョブの実行間隔に依存しない。
- 会話の統合は相手と窓口の両方が一致するときに許可する。元の番号と出来事を保存し、検索・表示・受信時に統合先の番号を解決する。同時に矛盾する統合が要求された場合は、一方の更新を拒否する。
- プレゼンスは5秒おきに更新し、最終更新から45秒経った表示を外す。返信欄への入力中はモードだけを送る。複数のタブを区別し、同じ運営者は1人として数える。

- 自動受付は最初の人間のメールだけを対象にし、運営者が窓口の登録または設定画面で有効化した方針を承認として記録する。迷惑メールの判定を受付返信側でも適用し、出口の配送順に依存しない。
- 作業時間 F は画面で閲覧した運営者が返信をキューに入れたときに計上する。
- チャットは公開記事の候補を Workers AI の Clef で採点し、製品のしきい値（既定0.6）を超えた記事を上位3件まで提示する。利用者は公開済みの記事本文を読む。[記事推薦の仕組み](dev/article-suggestions.md)
- 配送待ちの行にキュー投入の有効期限を記録する。全拡張を動かした受信テストで、並列コンシューマーによる同じイベントの過剰な再投入を検出したため。投入後に停止した場合は期限後に再開できる。

## 既定値として実装した項目

| 項目 | 運用開始時の動作と変更箇所 |
|---|---|
| 問い合わせ番号・差出人 | デプロイ全体の通し番号を使い、件名に番号を含める。差出人は会話の窓口で決まる |
| 運営者・権限 | Access で認証した最初のアドレスを管理者、それ以降を担当者とする。設定画面で役割を変更できる |
| 機械クライアント | 運営者が発行したトークンのハッシュを保存する。HTTP の MCP と CLI は代理人と権限を照合する |
| 拡張・自動返信 | 静的に設定し、管理者が有効化する。新規の人間からの問い合わせにだけ、自動であると明記した受付返信を送る |
| 隔離・通知 | 認証結果と自分の窓口からの送信を判定する。通知本文は既定で番号と件名だけ。Webhook や運営者へのメールは設定で宛先を指定する |
| 記事・チャット | 記事は D1 に Markdown で保存する。判断は Workers AI、公開する記事と閾値は導入先で設定する |
| issue | GitHub のリポジトリをプロダクト単位で指定する。投稿前に運営者が内容を確認し、番号と要約を送る |
| 検索・書き出し | D1 FTS5 の trigram で件名・差出人・本文を部分一致検索する。1〜2文字の検索は元データを照合する。JSON Lines には既定で相手の名前とメールアドレスを残さない |
| 受信上限 | 受信入口に渡ったメールが25 MiBを超える場合は原文と失敗記録を保存する。Email Routing が入口より前で拒否したメールは取得できない |
| 保存期間 | 無期限。期間を設定した場合だけ完了済みの本文と添付を削除する。相手単位の削除はいつでも可能 |
| 作業時間 | 画面で開いてから同じ運営者が返信するまでの時間を記録する |
| 実行環境・ライセンス | Node.js 24 と pnpm を使う。ライセンスは未決のため、ファイルの追加は所有者の判断に委ねる |

## 段階4の導入手順と診断

- 必須の binding とそのメソッドを Worker の各入口で検査する。AI を使う拡張は `requiresAI` を宣言し、有効なときに AI binding を検査する。既存のほかの拡張にこの宣言は不要。
- `SENDING_DOMAINS` を窓口のドメインと照合する。空の D1 でも最初の管理者は設定画面に入り窓口を登録できる。Cloudflare 側の送信設定を実際に読む処理は、運営者の端末で `helpdesk --live doctor` を実行したときだけ行う。
- セルフホストのローカル検証は手順書からコマンドを読み、依存関係と D1 の状態を作り直して実行する。書き出しは JSON Lines、既定では連絡先をマスクする。外部公開・ライセンス・本番ドメインは所有者が決める。
- 入口拡張が本人確認済みの会話に追記するため、既存の核の `addInboundMessage` を拡張のコンテキストにも公開する。同梱の公開フォームは新規の会話だけを作る。
- 受信は D1 に処理を予約してから原文を R2 に保存する。キュー投入の応答が失われても定期処理で再投入し、受信記録を確定する batch で予約を解消する。相手単位の削除は予約中の原文と添付も対象にする。
- D1 とローカルの workerd で FTS5 の trigram を使用できるため、日本語を含む部分一致検索の索引に採用した。既存データも migration で索引化し、削除や保存期間満了後には索引からも消す。[D1 の対応拡張](https://developers.cloudflare.com/d1/sql-api/sql-statements/)・[SQLite の trigram tokenizer](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

## 記事推薦のモデル仕様（2026年11月19日確認）

- 1回に送れる問いは1〜64個で、問いのキーは最大100文字です。記事のスラッグには120文字まで使えるため、候補を `article.0` などの短いキーに対応づけます。`noul` の結果は `answers[key].noul` から読みます。[入力スキーマ](https://developers.cloudflare.com/workers-ai/models/clef/schema-input.json)・[出力スキーマ](https://developers.cloudflare.com/workers-ai/models/clef/schema-output.json)
- Flash のコンテキストは24,576トークン、Clef は65,536トークンです。日本語の検索品質は導入先の記事と質問で測定します。[Clef Flash](https://developers.cloudflare.com/workers-ai/models/clef-flash/)・[Clef](https://developers.cloudflare.com/workers-ai/models/clef/)・[評価手順](reports/suggest-eval.md)
- 100万入力トークンあたり Flash は0.038米ドル、Clef は0.240米ドルです。料金の試算と見直し方は[運営ガイド](dev/article-suggestions.md)に記載しました。[Workers AI の料金](https://developers.cloudflare.com/workers-ai/platform/pricing/)

## 送信の取り消しと当日の集計

- 窓口の解決アンケートは日本語を既定にし、英語も選べます。過去に保存したプロジェクト別の案内と本文を優先します。
- 「過去7日」は運営者の現地日付で今日を含む7日です。開始は初日の最初の瞬間、終了は計測時刻を含みます。比較対象はその直前の同じ日数です。アカウントに IANA の時間帯名を保存し、未設定の運営者には日本時間を使います。夏時間で日が23時間・25時間になる地域でも暦の日で区切ります。
- Cloudflare Queues の送信・再試行の遅延上限は24時間です。10秒から5分の取り消し待ちはこの範囲に収まります。再配送を受けたときも D1 の送信予定を確認します。[Cloudflare Queues の制限](https://developers.cloudflare.com/queues/platform/limits/)
- 同じ会話への新しい受信と送信開始が競合した場合は、D1 の書き込み順で決めます。受信が先なら下書きに戻し、配送取得が先なら送信結果を記録します。「送信して完了」の完了時刻は配送が受理された時刻です。
- 承認後の待ち時間と「今すぐ送る」「取り消す」の操作権は、実際に承認した運営者にひも付きます。承認を取り消すと、同じ下書きと課題への紐づけを保って編集に戻れます。配送と新着受信の順序は、時刻が同じでも前後が確定する会話のイベント番号で比較します。

## 記事の候補に添える文

公開フォーム、ヘルプチャット、記事の一覧、運営者の返信欄には、公開済みの記事の最初の段落から2文までを表示します。候補を比べやすいように160文字を上限とし、長い文には省略記号を付けます。表示する文とリンクの取得には記事の公開状態を使い、AIの判定には従来どおり題と判定用の要約を使います。

## 会話の出来事とやりとり

会話の線は受信、返信、内部メモ、承認待ちの下書き、状態や担当者の変更を時刻順に表示します。閲覧や API の呼び出し自体は監査記録に残します。担当者・状態・同じラベルを同じ人が1分以内に連続して変更した場合は、最後の変更を表示します。メッセージをまたぐ変更は別々に表示します。11件目から先頭の1件と末尾の5件を残し、間の出来事も同じ折り畳みに含めます。

関連情報を開く前に示す課題は、会話の起票先にある課題から、すでに紐づいたものを除いて1件まで選ぶ。件名と最新の受信本文をローカルで単語に分け、件名での一致を本文の2倍に評価する。同点なら番号の小さいものを選ぶ。候補を押すと題を確認でき、運営者が確定した時点で紐づく。
